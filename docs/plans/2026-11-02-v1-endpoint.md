# SpiralCore v1 shared endpoint implementation

The architect/planner contract is [spiralcore-v1.md](../specs/spiralcore-v1.md),
with its machine-readable [descriptor schema](../api/spiralcore-v1.schema.json).
Implementation starts only after the parent reviewer accepts those files. This
plan is the bounded deliverable for the user's approved one-protocol/endpoint
standardization and canonical MVM adapter task.

## Selected design

Preserve SCMOBJ01 frames, mode IDs 0–9, object IDs, existing decoder formats and
all compatibility vectors. Add `spiralcore_transfer::v1` as the transport-neutral
public contract. The first MVM mapping explicitly pins full object-v1 and the
existing canonical content-type version 1. It does not invent network discovery,
a new envelope, or a replacement transport. The existing TUN service is not
claimed as an object-v1 endpoint, and stream/access profiles remain separate
future mappings of the shared contract.

The frame ceiling stays 65536 because current senders batch to fixed 60 KiB chunks
and DAG repair replies may exceed smaller limits. Validated object ceilings may
narrow and known codec sets intersect, with mandatory Raw. Advertisement metadata
must be authenticated by the carrier or explicitly pinned. Pure negotiation API
calls are not cryptographic authentication.

## Concrete implementation seam

1. Add validated `Capabilities` with version 1.0/profile1, codec mask, fixed frame
   ceiling and bounded object ceiling. `Capabilities::full()` supplies the pinned
   full profile. `Capabilities::negotiate(&self, peer: &Self)` yields immutable
   `NegotiatedProfile`; unknown versions/profiles/bits or omitted Raw fail.
2. Add `FrameEndpoint::handle(&mut self, &Context, &Frame, now: u64) -> Result<Frame>`.
   Keep a legacy receiver implementation for source compatibility. Add a fresh
   `ObjectEndpoint<A: Authority>` wrapper opened with `NegotiatedProfile`, root,
   limits, authority and optional cold-graph policy. It invokes core authority before codec/limit errors, then checks context shape,
   frame size without encoding a second copy, and Begin/Resume Offer codec/object
   bounds before delegation. The profile object ceiling applies to inbound offers;
   existing-store reads retain the global 64 MiB ceiling.
   Forward only required read/configuration APIs; no mutable-inner bypass.
3. Move the existing gateway-core `ObjectSender` implementation into transfer's
   v1 sender module, adjusting imports only. Gateway-core re-exports it. This is
   one sender, not a copy. Existing sender strategy and receipts remain intact;
   the full-v1 MVM profile does not imply dynamic narrow-peer candidate pruning.
   Add `new_with_profile(mode, context, schema, profile)`,
   `with_runtime_profile(context, prediction, profile)` and
   `with_combined_policy_and_profile(context, prediction, schema, policy, profile)`.
   Old constructors pin full v1 for compatibility. Store the profile immutably;
   all seed/send callbacks validate outbound frame bounds and Begin/Resume Offers
   before carrier invocation, then validate reply bounds. A narrowed Combined
   selection may return Unsupported with no transfer callback invocation;
   explicit Raw fallback remains a caller choice. No active-profile mutation.
4. Generalize canonical MVM VerifiedFrame dispatch over `FrameEndpoint`, retaining
   verified authority leases and revocation-generation checks. Make the live MVM
   campaign open the profile-enforcing shared receiver. Keep authentication,
   signing, envelope bytes, content-type and reply correlation MVM-owned.
5. Add contract tests before implementation: descriptor validity/version/mask
   refusals, codec/object-cap enforcement on Begin and Resume, exact shared
   sender/receiver reconstruction and canonical-MVM dispatch. Specifically assert
   Unsupported implies carrier callback count zero for an ineligible target Offer
   on every sender constructor family; include seed paths, Resume offers and
   oversized reply frames. Preserve legacy
   endpoint tests as compatibility coverage, not the claimed enforced-v1 path.
6. Measure the same public objects over the shared endpoint and canonical MVM
   adapter, recording actual frame/envelope/stream counts, setup CPU and verified
   commit elapsed. Linux/HVF live runs, when executed, retain their source/binary
   identities and profile accounting. No new WAN claim follows from API tests.
7. Run bounded standalone crate tests, strict Clippy and applicable Linux CI;
   obtain focused Rust/security/contract review, publish results and remaining
   gaps, then merge through a PR to origin/main without rewriting user work.

## First review checklist

- Both specification and schema agree on the exact descriptor fields and limits.
- No v1 wire-byte or mode-ID change is hidden behind API extraction.
- Shared receiver profile checks precede underlying admission/state mutation.
- Caller-supplied context is not mistaken for authenticated authority.
- Pinned MVM agreement is clearly different from dynamic wire negotiation.
- No duplicate sender implementation, MVM envelope or codec decoder is created.
- Every sender carrier callback enforces the immutable profile, including seeds;
  unsupported chosen target Offers reach no carrier callback.
- Different endpoint semantics are versioned explicitly rather than disguised
  as interchangeable packet/message/stream acknowledgments.
- Measurements include compute and seeding, retain losses, and identify their
  byte/accounting layers.
