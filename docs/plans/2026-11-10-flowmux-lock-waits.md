# Plan for release-driven Session and TX waits

Implement the [ownership-wait contract](../specs/2026-11-10-flowmux-lock-waits.md) on the existing Windows repair branch based on `16efe4c2586fd627dbdfedaf0f982a8331a2ac54`. This is one behavioral performance repair backed by the sustained witness. Preserve other contributors' changes and original evidence.

1. Add one private std mutex/condition-variable wrapper and original-guard wrapper. Start with deterministic RED tests for release racing waiter enrollment, cancellation before wait enrollment while data stays held, release without progress, spurious wake, original absolute deadline and actual std mutex poison. Check the original stopped atomic under the gate; keep full authority callbacks outside it. Keep protected data behind its original mutex. Use `lock_until(until, stopped: &AtomicBool)` and check the original atomic under the short gate immediately before try-lock and waiter enrollment. Full scope/authority checks remain outside the gate and run again before guard exposure. Add no Cargo dependency or unbounded registration structure.
2. Integrate TLS Session first. Retain current nonblocking session/readiness distinction, releasing peek's poller before waiting. Notify on every data guard release and owner stop, including error and unwind. Stop stores original Shared.stopped before synchronizing notification under the gate. Exercise existing readiness, lost-wake, closed-owner, EOF and stalled-deadline tests with timing both enabled and disabled. Review lock ordering before native execution.
3. Integrate shared TX through the same primitive. Cover sender exchange, receiver response, half-close and incidental TX snapshot access. Add a single fixed weak cancellation wake binding to the original gate before the worker starts. Expose only the original Control.stopped atomic through crate-private Cancellation::stopped_flag. Control close stores it before synchronizing notification under the gate. Never invoke a scope-locking cancellation callback inside that gate. Test conflicting registration refusal, cancellation while another thread holds TX, matched response, and data/gate poison. Keep pending/response order and original errors.
4. Extend existing bounded timing buckets for ownership-wait requested/actual time and outcomes. Remove only Session/TX one-millisecond park observations replaced by these waits. Existing network-readiness waits remain observable. Record exact fixed synchronization storage and preserve SmallV1's core envelope with any witness-only overhead explicitly charged.
5. Run focused portable tests and strict Clippy, then the existing native Windows 2025 failing component witness with the same synthetic inputs, authority and 4,096/240-second gate. Retain actual CPU, wall, bytes, write/ACK/read ordinals, scopes, cache bounds and lock/poll spans on success and failure. Use the same feature setting as the prior timing record. Do not infer send-only latency from nested waits.
6. Obtain independent code/security review of lost-wake, poison, cancellation and release ordering before merge. Qualify remaining native roles through the existing matrix and confirm normal feature-off acceptance. If the gate still fails, use Commit processing and receiver/TX timings to select one next measured change. Avoid bundling unrelated creation-security-descriptor cleanup into this experiment.

The implementation should remain confined to a private lock-wait module, FlowMux TLS/duplex/control integration, timing buckets and focused tests. Neither storage algorithms nor MVM startup accounting change in this slice. A native result establishes the exercised component workload, with larger WAN and installed-service gates tracked separately.
