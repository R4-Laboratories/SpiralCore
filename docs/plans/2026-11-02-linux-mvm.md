# Linux/Firecracker mailbox parity

## Decision and scope

Use MVM's existing `FcDriver`/`VmmSpec` seam to boot the same bounded synthetic
guest workload used by the HVF witness. Do not create an alternate packet path,
guest NIC, mailbox envelope, signature domain or transport authority. Existing
canonical envelope creation/verification and scoped object reconstruction remain
the shared core. This delivers an experimental cross-backend witness, not closure
of upstream #4629's production service or #4607's network-adapter decision.

The Linux guest dials the dedicated mailbox port. `GuestService::Mailbox` with
`VsockDirection::GuestDials` lets the MVM Firecracker driver map its per-port
Unix socket to the orchestrator's already-bound listener. The Firecracker mux
`CONNECT` protocol is for the opposite direction and must not be substituted.

## Implementation

1. Add Linux host dispatch while retaining guest-as-init dispatch and the existing
   HVF host entry point. Use one backend-specific host module behind the shared
   orchestrator interface.
2. Build a bounded initramfs for the host architecture (x86_64 ELF or ARM64 ELF).
   Keep credential-bearing initramfs in an anonymous Linux memfd held through
   synchronous boot setup, rather than writing it to a public experiment file.
3. Boot an explicit kernel, 1 vCPU, 1024 MiB memory, optional 256 MiB ext4 data
   disk, write-only console, the dedicated guest-dialed mailbox service and MVM's
   existing typed workload-exit service. The exit service remains present during
   keyless readback, when no mailbox channel or encryption key is provisioned.
   Do not declare MachineControl for this synthetic init: that would make the
   driver await an agent it does not run. No NIC is present in VmmSpec.
4. Give every worker an isolated private `MVM_HOME` and unique VM name. Track and
   clean up only the VM this worker owns. Preserve failed public receipts without
   disclosing bootstrap/initramfs contents.
5. Parse bounded public guest events, require exactly one successful completion
   plus a zero canonical workload-exit code, validate ready-clock offset,
   explicitly terminate the owned VMM, observe its exit through pidfd and sync
   the retained backing disk. This is application completion plus owned host
   termination: x86 Firecracker does not naturally exit on guest poweroff.
   Reboot readback uses the existing keyless verification stage.
6. Keep canonical ACK, framing, authorization and reconstruction semantics.
   The MVM HVF mailbox rate budget is crate-private and the Firecracker typed
   guest-dial bridge does not apply it. Linux receipts must explicitly report
   `mailbox_rate_enforced=false` and null effective rate/burst, preserving the
   requested profile separately. Compare all Linux arms under the same declared
   unshaped condition; do not claim rate-policy parity or pool Linux and HVF
   measurements. A shared enforced rate profile remains an explicit follow-up.
7. The Firecracker VMM is detached from the worker. Parent cancellation must run
   the owned cleanup subcommand with that worker's private MVM_HOME and PID after
   reaping the worker, so SIGKILL cannot bypass the worker's normal RAII cleanup.

## Evidence and tests

Focused tests cover architecture/header rejection, bounded bootstrap packing,
completion/malformed/duplicate event rejection, required clock fields and offset
bounds, and Linux NIC-less/typed-service launch configuration. Compare warm/raw/
whole-zstd/Combined with exact byte comparison and durable reopen for one guest
then two guests. Retain source/binary/fixture identities, both directions' envelope
and framing bytes, sender/receiver CPU and elapsed time, setup and boot separately.

Host worker ProcessTime excludes the separate Firecracker process. Report its
CPU separately from guest CPU and worker CPU, with no claim of total host CPU
where process accounting is unavailable. Never label mocked tests or a build as
a KVM run. The approved Wick run is the Linux execution target; unavailable KVM,
kernel or canonical-service assumptions remain recorded blockers rather than
skips. Cross-host/Iroh, 1000-identity contention, and Windows remain subsequent
work under Ari's respective issue contracts.
