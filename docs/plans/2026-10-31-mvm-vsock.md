# Implementation plan: real MVM guests over the experimental mailbox binding

Date: 2026-10-31. Implements [the approved local integration contract](../specs/2026-10-31-mvm-vsock-design.md).
Scope: one native HVF Linux guest/host, then two guests and a bounded local
orchestrator. MVM source pin is `3104a12c5b071a6851323fa8115d2afaf3f0bb8b`.
No upstream publication, Iroh, full fleet integration or new codec optimization.

Implementation status: both live stages have passed. The retained pilot contains
100 exact transfers across 12 sessions and 50 exact readbacks after a separate
keyless receiver reboot. See the [result report](../network/mvm-vsock-results-2026-10-31.md)
for source identities, timings, failures and the narrower qualification boundary.
The service uses an exclusive serial owner with no concurrent policy-update path;
it does not implement a policy mutex spanning an endpoint operation.

1. **Preserve provenance and establish the live environment.**
   Use the isolated MVM worktree prepared by the root task; never change Cargo's
   cached checkout. Record exact source revision, base blobs, source-patch hash,
   Rust/cross compiler, macOS/HVF capability, kernel and guest image identities.
   Reuse installed kernels/artifacts only after their identity is verified.
   Apply the native HVF live-test exception; no host Nix, ordinary mvmctl, Lima
   or billable remote VM. Record unavailable ponytail/rust-skills and Graft.
   Check disk before building, use a shared existing target where compatible,
   disable incremental debug growth, and preserve only bounded evidence.

2. **Write failing contract tests for the two upstream accessors.**
   In the isolated source patch, test that an authorized frame exposes exactly
   its encoded immutable bytes and that requested channel bounds are readable.
   Test a new verified-open result's authenticated header/payload, malformed
   signature/key/replay rejection, and unchanged legacy `open_envelope` behavior.
   Observe RED before implementation. Implement the private proof type by moving
   the existing canonical verification into one shared path, not by duplicating
   decryption/signature checks. Preserve MVM wire formats and defaults.

3. **Write failing dedicated-service and HVF bridge tests.**
   Add the shared 5257 constant and semantic `GuestService::Mailbox` contract.
   Test no service collision, correct label, absent-binding refusal, bidirectional
   relay with a dedicated UDS, independent budget and clearing/rebinding. Thread
   `mailbox_endpoint` through `VsockHostBindings` and `mailbox_socket` through
   `HostChannels`/`RunInputs`; update exhaustive struct construction sites.
   Register `StreamRelayHandler` using existing bounded machinery. Do not add
   mailbox to trusted-builder exemptions or borrow egress/console bindings.
   Snapshot handoff is refused by the live runner; never silently inherit it.

4. **Implement the live canonical session around the existing codecs.**
   In SpiralCore, add strict discriminator/length framing and an actual stream
   `PeerTransport`/`PeerChannel` implementation using the authorized byte accessor.
   Test split reads/writes, oversize/truncation, EOF, cancellation, deadline and
   poisoned-stream behavior. No transport serialization wrapper is added.
   Implement `PendingCall`/`VerifiedCall` and authenticated correlation/causation
   using verified upstream headers. Keep receive-only configurations free of
   remote private signing keys. Test wrong/late/unsolicited replies and exact
   existing frame recovery before writing the guest runner.

5. **Close the live authority gaps.**
   Add real UTC refresh, monotonic call deadlines and expiry checks at final
   authority use. Apply the explicit five-second clock profile: live-only issue
   backdate, unchanged canonical verification, actual UTC plus five seconds at
   final expiry checks, no more than 35 seconds signed issue-to-expiry and 30
   seconds local call lifetime. Provision grant/route not-before ten seconds
   before fresh bootstrap, verify the pairwise guest clock bound and refuse stale
   boot timing. Separate time refresh from revocation/epoch generation changes.
   A single session owner serializes open/handle/reply. The live witness has no
   concurrent policy-update path; public API users must provide their own
   exclusive ownership across policy changes and endpoint work.
   Enforce granted rate, queue and outstanding-call limits plus the fixed service
   bounds. Keep replay bounded without eviction. Preserve fresh-envelope
   application retry and explicit `WarmSession::recover`; emit no mailbox durable
   acceptance claim. Cover expiry during work, policy changes, lost replies and
   process/store restart with focused tests.

6. **Build a minimal Linux guest binary and native HVF test runner.**
   Reuse `mvm_agentd::vsock::sys::dial` for the guest's CID2/5257 connection;
   reuse MVM's public `boot_kernel_until` builder for the host worker. The runner
   creates its ephemeral keys/configuration in memory and passes secret bootstrap
   data through private pipes/in-memory initramfs, never argv/env/evidence or a
   persisted unencrypted image. Use the existing workload-exit reporting where
   applicable; console output contains only public lifecycle/result metadata.
   Arm UDS/readiness and process-exit events before boot. Sign the native runner
   with the required Hypervisor entitlement. Add a fresh writable guest cache disk
   only for receiver persistence tests; record logical and physical disk sizes.

7. **Prove one actual guest/host.**
   Start the host endpoint before the guest. Run raw, prepared whole-object zstd
   and WarmSession through identical canonical framing with one persistent host
   receiver. First send 1 MiB cold/repeat/localized/unrelated/length-change objects,
   then 16 MiB after success. Independently reopen and compare exact bytes/length.
   Record both endpoints' CPU, operation elapsed, canonical/prefix bytes and setup
   costs. Include a registered shared-runtime/ternary/CA object. Test absent
   mailbox binding, disconnect and lost publication reply. If boot fails, retain
   a compact diagnostic and fix the concrete environment fault; do not replace
   the live test with a mock or label it successful.

8. **Prove two actual guests under one small orchestrator.**
   Launch two distinct HVF worker processes, private UDS paths, key sets and
   lifecycles. Guest A generates/encodes; guest B opens/decodes/publishes. The host
   forwards only bounded canonical envelopes between the two admitted routes.
   Authenticate requests and replies at the guests; host route filtering is not
   principal authorization. Repeat the same 1/16 MiB paired workloads and measure
   each physical hop separately. Guest B reopens its cache and compares exact
   bytes with an independently generated public fixture outside that cache.
   Exercise receiver-process restart and fresh-envelope recovery within the same
   running epoch. After graceful stop, boot a separate read-only verifier with no
   mailbox/signing configuration to compare historical-namespace persisted bytes.
   Do not label this a new-epoch authorized resume: live owner restart rotates
   BootId/epoch and needs an explicit cache migration mechanism, deferred here.

9. **Package and qualify the actual result.**
   Export the exact local MVM diff plus base/patch/source identities into a small
   SpiralCore integration bundle; make application verify its base before editing.
   Keep raw JSONL metrics and narrow test logs, executable/kernel hashes and
   limitations. Record actual receiver storage type and whether reboot durability
   was tested. Preserve the inherited relay rate limit in the report and do not
   interpret local HVF times as WAN speeds. Run relevant Rust tests/Clippy and the
   MVM gated checks for changed shared types; list any unrun full-workspace gate
   before describing upstream readiness. Clean only owned stores/images/processes
   after verifying results and teardown. Do not close #4629/#4633 or send Ari an
   upstream change without separate publication authorization.

The first meaningful completion is a recorded real guest/host transfer with exact
recovery. The delivery target for this plan is that result plus the two-guest
orchestrator witness; source-only unit tests do not satisfy either live gate.
