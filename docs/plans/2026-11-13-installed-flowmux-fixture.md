# Installed FlowMux fixture implementation

The project owner approved the [fixture design](../specs/2026-11-13-installed-flowmux-fixture-design.md) on November 13, 2026. Deliver a reproducible signed role to the existing installed witness. The example runs on x86-64 Linux using the pinned canonical-host SDK. Track source and native evidence in [issue 261](https://github.com/R4-Laboratories/SpiralCore/issues/261).

Paths below are relative to `crates/spiralcore-mvm-live`. Each numbered step is a separate change of at most 50 implementation lines. Stop at a source or dependency mismatch and record it before expanding scope.

1. **Target and failing controls.** In `Cargo.toml` declare the feature-gated example. In `examples/installed_flowmux_fixture.rs` and `examples/installed_flowmux_fixture/tests.rs`, exercise invalid IPv4, wrong staged ELF digest, occupied output, unsafe output parent and mismatched baked argv. Check refusal reasons and preservation of existing bytes. Capture five failing assertions before implementing. Low risk.
2. **Input checks.** In `stage.rs` in the same example subdirectory, validate exact four arguments, SHA syntax, canonical IPv4 and a fresh absolute output path below an operator-owned private parent. Refuse aliases and replacement. After step 1, run the argument and output selectors. Medium risk.
3. **Stage the ELF.** In `stage.rs`, copy the opened regular x86-64 guest ELF to a private tree and verify the actual staged bytes against the operator digest. Use the same retained bytes for materialization; keep guest program directories traversable after the workload UID drop. Run the wrong-digest control. Medium risk.
4. **Admitted inputs.** In `package.rs`, require explicit private producer home, load its existing signer, capture the current signed revocation document and signature, and acquire the official release through `PreparedPortableBootAssets`. Refuse missing or stale inputs. Depends on staged ELF. High trust impact.
5. **Role and image.** In `package.rs` construct one validated environment and `ImageRuntimeConfig` with the same fixed argv and destination. Use the original runtime binaries and in-process sealed image builder. Read back and compare the sidecar before signing. Run the argv selector. Medium risk.
6. **Sign and reopen.** In `package.rs` bind kernel, initramfs, verity, sealed egress posture and resources in `BundleExportInputs`. Stage and publish with the canonical host signer. Independently reopen with the preselected public key, recheck environment, current revocation and exact archive identity. High trust impact.
7. **Publish.** In `stage.rs` write only the reviewed public packet members with owner-only permissions, sync them and publish without replacement. Keep work files outside the packet. In `installed_flowmux_fixture.rs`, dispatch on supported Linux and report unsupported platforms before effects. Medium risk.
8. **Qualify.** Run `cargo test --locked --features canonical-host --example installed_flowmux_fixture` and strict example Clippy. Capture a genuine signed export, independent archive verification, and one boot through the existing witness runner. Record original identities, 5,804-byte readback, both TLS counts, CPU, elapsed time, signed audit and original retirement. Link the exact outcome under issue 261. VM and remote WAN claims retain their independent evidence requirements.
