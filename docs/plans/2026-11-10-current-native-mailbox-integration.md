1. Write RED tests against current canonical APIs. A verified-open test needs authenticated header/payload without a public constructor, verifies replay is recorded once, and confirms existing open returns identical payload/errors. Negative cases alter header signature, payload commitment, recipient, epoch or revocation and must produce no proof. Add outbound tests for Reply-only success, Reply under Send refusal, Call/Cast under Reply refusal, mismatched route and exact authorized ciphertext bytes.

Run core mailbox/transport tests, no_std contract check and independent security review. Keep existing `AuthorizedMailboxFrame::as_bytes`; do not add redundant getters. Use public synthetic bytes within the existing 16 KiB default capability and record exact length/readback and helper lifetime. This establishes the current endpoint before changing its delivery behavior.
4. Add canonical service-version RED cases before producer changes. Legacy recipient/body still decodes exactly. An unadmitted new version refuses without consuming the producer slot. Accepted IDs bind VM/grant/boot/epoch and immutable request content. Refuse ID conflicts and unrelated producer requests. Keep declarations/types in MVM's existing protocol module, with signed-launch selection and no competing envelope.
5. Add deterministic mock-I/O RED tests for lost verdict, QueueFull, concurrent next write and reconnect. Claim survives ambiguous/refused transmission, next write cannot overwrite it, retry reuses stable semantic identity and has one admission disposition. Then implement guest retained outbox and bounded host prepared-envelope/dedup state. Model retained bytes/IDs against aggregate credits and check current authority before retry acknowledgment. Test epoch restart without claiming exactly-once application execution.
6. Add the admitted return lane and correlated Call/Cast/Reply RED cases using the original service/process. Cover two simultaneous Calls with reversed Reply order, cancellation, deadline expiry, delayed Reply after a later Call, Reply-only grants, destination epochs that differ, receipt-control nonrecursion and saturated data with reserved control progress. Reuse proven downstream service/receipt logic where compatible, moving ownership into canonical MVM service rather than adding a parallel helper.
7. Run one guest/host native exact object-v1 transfer through both admitted directions. Count setup, manifest/residual, admission receipts and application responses, actual authenticated traffic, sender/receiver CPU and verified total time. Repeat exact warm transfers and localized edits against equally tuned zstd under the same durable/ephemeral contract. Preserve losses and refusal evidence.
8. Prove stop/reap while idle, during a stalled peer and with retained retry state. Then two guests and existing recovery/scale/WAN gates can proceed. Keep FlowMux and owner access on their own declared services and policy paths. Prepare the authorized upstream contribution from this current source after reviewed tests and native evidence, preserving unfulfilled tracker criteria.
