# Windows quota scans with a bounded directory owner

Status is an architecture decision for the PR #106 Windows performance repair. The scalar implementation is in progress. MSVC metadata compilation and Clippy passed. Native security and performance qualification remain pending, and no speedup is established.

The Windows Server 2022 run 42894601561, job 130104398191, completed the 129-block case in 5.78 seconds. The sustained case reached 2,626 and 2,619 blocks before its 240-second watchdog, with 64 publications, one attempt and 1,051,712 cache bytes per side and current scopes. The sustained count, deadline and authorization checks remain acceptance gates.

`Endpoint::disk_usage` scans publications at each admission. Each Windows `quota_file_len` currently calls `open_read`, which normalizes the path, reopens ancestors, checks the volume, obtains the effective SID, constructs a security descriptor and checks the held file. Repeating that setup for every file is the proposed optimization target. Timing evidence must establish its actual contribution.

## Alternatives

A cached quota index would replace filesystem observation with retained lengths. Reject this alternative for this slice. External growth, replacement, ACL changes and missing files would make the index an insufficient admission budget check. Making it authoritative requires a separately enforced immutable storage owner and reconciliation contract.

Adopt an isolated native directory batch for one synchronous namespace scan. Its lifetime covers enumeration and held-file metadata checks. Normalize and validate the namespace and ancestors once, hold their handles, and reuse the established volume and directory identity. Each publication still receives a fresh held-file check of type, reparse status, link count, effective SID, protected owner-only ACL and sharing, followed by a checked length. The batch returns only checked scalar totals and count. No identity, filename, handle or payload reader escapes.

## API and ownership

Add only the Windows-native synchronous function `quota_usage(root, scoped_namespace, max_files, namespace_filter, extension) -> Result<(u64, u64, usize)>` in `spiralcore-storage-windows`. `namespace_filter` is a trusted noncapturing string predicate. The returned tuple is total bytes in the requested namespace, aggregate bytes and publication count. The transfer-layer Windows mapping delegates its quota scan to this function. Unix keeps its current implementation.

A private `QuotaRoot` owns the normalized root, original SID, volume identity, strict ancestor pins and internal GUID path. It discovers canonical immediate namespaces through that anchored root and visits each selected namespace through its own anchored GUID path. Retain one namespace pin and one publication handle at a time in addition to the root ancestry. Stream entries without collecting names or records into a vector. Checked count and byte additions enforce the caller's existing limits.

The batch ends before publication, eviction, cancellation or another admission operation. Ordinary content reads retain their current implementation. The API exposes only scalars, with no opaque directory, path, iterator or handle escaping to a caller. No Unix wrapper, persistent batch cache, protocol change or permission repair is needed.

## Path and token invariants

Preserve the current drive-absolute NTFS profile and normalization rules. Reject UNC, device paths, alternate data streams, traversal, trailing-dot/space aliases, noncanonical child components, reparse points and non-disk objects. Children must be one component beneath the retained namespace. Check each child's volume against the original held namespace.

The older ancestor handles request attributes and READ_CONTROL. They do not establish deletion or rename exclusion merely by omitting share-delete. Sharing checks depend on requested access, so the batch must request `FILE_LIST_DIRECTORY | FILE_READ_ATTRIBUTES | READ_CONTROL` and allow only `FILE_SHARE_READ`. The list-directory access participates in sharing enforcement. Require those access and sharing flags for every original ancestor, root and selected namespace pin. A conflicting open refuses accounting. Qualify the exclusion with actual root and namespace rename attempts while pinned and success after release. [Microsoft sharing algorithm](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/8c0e3f4f-0729-49f4-a14d-7f7add593819)

Derive a private kernel-resolved path from the original held namespace using `GetFinalPathNameByHandleW` with `FILE_NAME_NORMALIZED | VOLUME_NAME_GUID`. Bound the UTF-16 buffer and returned length, require the expected volume-GUID form, reject embedded NULs and malformed components, and retain this path only inside the native owner. Public callers continue to supply the existing approved drive-absolute form. Microsoft documents the normalized-name and volume-GUID flags and the buffer-sizing contract. [Microsoft API reference](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew)

During root-chain acquisition, require each held directory to belong to the original volume and its normalized GUID parent to equal the previous held directory's GUID path. This refuses a mixed chain acquired through a changing alias. Open each selected namespace as an immediate child through the retained GUID root, validate its current-SID private directory ACL, same volume and normalized final parent, and enumerate its GUID path. Open each validated publication basename beneath that GUID namespace. Hold all original ancestor and namespace handles with share-read only, recheck their directory/reparse information, and require the opened file to belong to the original volume. Require the leaf's kernel-resolved normalized GUID parent to equal the retained canonical parent. Compare canonical UTF-16 components using Windows ordinal case semantics or refuse an unequal exact kernel spelling. Avoid user-controlled case folding and string-prefix ancestry checks. Retained volume/root handles and directory identity pin this scan to the selected local volume. A failed path query, identity check or sharing check refuses the scan.

Enumeration also belongs to this anchor. Native batch enumeration must read the internal GUID namespace and return only aggregate lengths and publication count. Leaving `fs::read_dir` on the original drive-letter path would permit an empty or foreign enumeration despite anchored child opens. Root namespace discovery must use the equivalent held root and internal GUID path so it cannot omit a quota namespace after an alias change. Keep all iteration inside the synchronous scalar function. The backend can reuse standard directory iteration over its private GUID path while retaining the directory pins.

This design avoids reopening an ambient drive alias and needs one additional Win32 path-query helper. It qualifies only after native tests establish share-mode pinning across every supported Windows role. If those pins cannot exclude reparse mutation, require a separately reviewed handle-relative child open before bypassing repeated ancestor validation. A privileged actor capable of dismantling the selected volume lies outside the ordinary private filesystem profile. Refuse observed identity or filesystem changes.

Keep the batch bound to its original thread and a synchronous scan. Keep the private native owner non-Send and non-Sync, and expose no owner value. Query the effective SID at each metadata operation, compare it to the opening SID and apply the existing held-file ACL checker. An impersonation change refuses the batch. Existing `OpenThreadToken` error handling must preserve process-token fallback solely for `ERROR_NO_TOKEN`. File opens still use the current effective token. No process SID cache or temporary impersonation reversal is permitted.

A full-control security descriptor is unnecessary for an `OPEN_EXISTING` metadata query. Reuse the current ACL validation function while avoiding creation-descriptor construction. Preserve the existing `GENERIC_READ | READ_CONTROL` open rights and `FILE_SHARE_READ` publication-file sharing for this slice, while keeping those handles inaccessible to callers. File-size admission retains the existing exclusion of concurrent writers and deletion. The API cannot expose these handles as a content-reading capability.

## Focused regression gates

Extend the two existing native backend ACL and junction suites in `spiralcore-storage-windows/src/tests.rs`; their added checks remain part of those suites. Cover a valid multi-file scan and exact lengths, broad and inherited ACL rejection on a later child, hardlink and reparse child rejection, and an incompatible writer. Ensure the batch releases all handles on refusal and drop.

Add a controlled namespace or ancestor replacement attempt during the scan. It must fail the mutation under held sharing or make the accounting operation refuse. Include same-volume junction redirection, volume-GUID final-parent mismatch, bounded final-path buffer failures and a changed drive mapping where native test authority permits it. A changed alias must either preserve the original anchored enumeration and lengths or refuse, and must never yield an empty successful scan of a foreign directory. An unavailable privileged negative must be recorded explicitly. Add handle-kind and anonymous-impersonation identity refusal cases, preserving the caller's original token. Include root and namespace rename refusal while pinned and successful rename after release.

Reuse transfer endpoint quota cases for exact aggregate and scoped totals, quota exhaustion, growth between scans, malformed namespace skipping, publication count limits and overflow. Reuse ordered retention and Small resource regressions to prove that eviction, setup pins, retry retention and exact publication retain their bounds. Content-read verification remains covered by its existing path.

Record six paired scans over 64 files through the previous per-file metadata path and the new batch, including exact totals, process CPU and wall time. Then run native Windows primitive suites and the existing seven-role CI component matrix. Compare before/after 129-block and sustained workloads with the same counts, watchdogs, security checks and pinned fixtures. Record CPU and wall time plus actual byte counters. Source compilation alone does not qualify the path or establish a speedup.
