# Schema fitting as shared prediction state

**Proposal; unimplemented and unmeasured.** Recorded 2026-10-30 following Jeff Venable's suggestion, against SpiralCore `773f7cc5f5ea23044053fec6a41e70f52e092534`. This note adds no codec, package, protocol change or experiment.

A shared schema can make recurring structure cheaper to describe and cheaper to predict. The useful hypothesis is that endpoints retain the same bounded layout, literal dictionary or template, then exchange only the values and exact residual needed for each record. A schema describes regularity; it does not supply unpredictable information. Its benefit must include the cost of fitting, distributing and retaining that shared state.

This extends the existing `verified state + recipe + exact residual → original bytes` design. The coupled ternary/Kuramoto/cellular-automaton runtime remains central: its versioned transition profile and checkpoint form a dynamic schema family. Declarative record templates and dictionaries would be additional families using the same identity, admission and durable-commit contract. The first implementation should use a small allowlisted Rust decoder with bounded operations, output, depth and retained state. Received schemas are data, never source code or arbitrary executable decoders.

**Preserve the original bytes.** For JSON, equal parsed values are insufficient: whitespace, field order, duplicate keys, escape spelling, numeric spelling such as `1`, `1.0` and `1e0`, and line endings all affect object identity. A template could retain common punctuation and key bytes while carrying exact raw token spans; any remaining difference belongs in the residual. Parsing failure or an unsupported form must retain a literal/raw path. The final length and whole-object digest still verify the exact original byte string before publication. Schema fitting must not silently replace input with normalized serialization.

Two conventional references help define the comparison. Zstd trains a dictionary on correlated records and loads it for compression and decompression; its small-record use case is directly relevant to repeated structured messages. This is an existing baseline, not a new SpiralCore claim. [Zstd small-data compression](https://github.com/facebook/zstd#the-case-for-small-data-compression) Avro's single-object encoding identifies the writer schema through a fingerprint before decoding the record. That illustrates layout identification across schema versions, but adopting a semantic serialization format would not by itself preserve the spelling and layout of an original JSON document. [Avro 1.12.0 single-object encoding](https://avro.apache.org/docs/1.12.0/specification/#single-object-encoding)

**Identify, admit and evolve immutable artifacts.** A proposed schema ID is a full domain-separated SHA-256 digest over an unambiguous, length-delimited descriptor binding the exact template/dictionary bytes or their full digests, format version and allowed decoder-profile version. Runtime-backed variants also identify their checkpoint and transition profile. Each transfer names the exact artifact and decoder version; a human-friendly schema name or mutable “latest” pointer is insufficient. This identity is distinct from the unchanged identity of the final object and does not grant permission.

The receiver must admit the artifact under the recipient, tenant/domain, capability and policy/execution epochs, verify its bytes and supported profile, and reserve bounded decoding resources. Cache membership and schema availability remain scoped disclosures. An unknown, evicted or unsupported schema permits an explicit sender choice: send raw/zstd, or transfer and admit the missing artifact before a new schema-dependent transfer. A miss after Begin fails that attempt; no silent decoder substitution, implicit reoffer or publication of a partial result. Revocation and resume use the existing authorization checks. Evolution creates a new immutable ID; in-flight transfers remain pinned, subject to current policy.

**Decoding needs endpoint agreement, not global consensus.** The sender and authorized recipient agreeing on the immutable artifact ID and decoder contract is enough to reconstruct one transfer. “Shared understanding” here means a common interpretation of fields and bytes. A global consensus mechanism is relevant only if the application requires coordinated changes to a mutable network-wide schema choice or other shared state. A small orchestrator can instead own an authorized schema registry where that authority model is sufficient. Kuramoto coordination does not replace artifact identity, epochs or authorization, and this proposal makes no physical-clock agreement claim.

**Smallest next Rust benchmark, if implemented:** fit one bounded literal/template family from a training split of repeated structured records, freeze its artifact, and evaluate held-out records. Include exact lexical variants, new/missing fields, field-order changes, unrelated records and a later drift segment. Keep the current coupled-runtime family in scope; do not refit on the held-out answers. Compare raw, ordinary zstd, current prefix/delta selection and a trained-zstd dictionary using the same inputs, admission conditions and verified durable commit.

Record both directions' transfer bytes, schema/checkpoint seeding, misses and fallback, refitting and redistribution, retained memory, fitting CPU, sender encoding CPU, receiver decoding/replay CPU, and total elapsed time. Keep nested timing scopes distinct. Report cold cost and amortization across successive records, including when the schema stops paying for itself. Byte reduction with zero loss remains primary; superiority over the best conventional baseline and any CPU/time benefit require measurements. MVM integration remains subsequent work.
