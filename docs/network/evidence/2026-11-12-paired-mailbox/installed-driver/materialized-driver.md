# Materialized role images and late coordinator exit

An SDK `LocalPath` directory triggers an image import that rewrites the runtime-owned configuration. The addressed witness now takes two operator-materialized ext4 files, each with a canonical MVM sidecar and verity metadata. It checks the input path, file ownership, protections on each ancestor, bounded metadata sizes and MVM’s build-completeness validator before requesting either launch. The operator independently verifies the image, executable, wrapper and full verity tree against trusted inputs. [Driver and reproduction](../../../../../tools/installed-mailbox-witness/CAST.md)

Each role emits a stable SDK result as soon as its launch returns. When the coordinator misses its retirement deadline, the witness writes and syncs the failed report. It then waits in the original parent on the retained child. A later exit is recorded in a separate `.coordinator-exit.json` file. The first report keeps its failure and original lifecycle time. Observation can continue for the lifetime of a stalled process.

The Linux x86_64 library suite passed all nine tests. The role test covered directory import refusal, incomplete sidecars, group-writable ancestors, an oversized root hash and a symbolic link. The diagnostic test checked stable output for an SDK error containing private text. The child-process test held the original child open through report publication, observed its subsequent exit and repeated the exercise with a failed report sink. The addressed CLI typechecked against the same MVM source. The suite started zero VMs. [Selectors, binary and log identities](materialized-driver.json)
