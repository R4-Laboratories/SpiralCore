# Destination guest object worker

The Rust worker now handles a selected, signed mailbox Call in the shared SmallV1 receiver. On Linux x86-64, a real worker process and the MVM guest-agent reader processed one 102-byte object Offer in an isolated mount namespace. A synthetic host fixture dropped the first result for the computed Reply and refused the second. Both submissions carried the identical Reply and original lease. B issued zero ACKs. [Exact counters, source and binary identities](destination-worker.json)

Five fresh authorization exchanges accounted for 10,330 B toward the agent and 38,999 B back. Guest-local Receive, staging and status accounted for the other 3,038 B and 4,670 B. Counts include completed application-socket reads and writes during the failed transfer. Worker pipe inputs and the guest-agent-to-host fixture socket are outside these meters. The complete unoptimized component test used 0.20 s user CPU, 0.00 s system CPU at the timer’s precision, 0.21 s wall and 10,800 KiB peak RSS. One synthetic Offer produced no destination V2 or terminal object readback. Actual guest, WAN, energy and compression savings remain unmeasured for this path.

## Authority and recovery

The local receiver requests fresh authorization for the exact Call at each cache authorization point. The original host provider looks up the still-unacknowledged journal row, checks both original native participants, the signed Call and independent Receive authority, the authenticated header, the return route and expiry. The guest reader binds its existing possession key to the signed role, signed lease, selected pair and fresh application nonce. The application verifies against the public reader binding installed from its own identity drive. The ordinary mailbox listener refuses the selected operation. [MVM source](https://github.com/Casey-allard/mvm/tree/72684d46277dbfe545616f72490fc940c5718680)

The B worker accepts `object_receive` with the original pair, transfer and frame sequence. It keeps one private receiver for its boot and one outstanding original lease. Once it computes a Reply it retries that exact value after ambiguous I/O. A fully decoded refusal fences the retained Reply. After A’s verified V2, B retries only its signed Call ACK. A terminal publication or cache hit reads the stored object and checks its identity while the Call remains authorized. The successful result carries its exact bytes, a worker-instance identifier and B's boot identifier. If application output is lost after a successful ACK, retrying reports the historical ACK. A new authorized Call is required to recover plaintext again. Losing the worker process leaves its prior boot-specific cache closed to automatic reattachment. [Worker entry and settlement code](https://github.com/R4-Laboratories/SpiralCore/tree/90e92ddeefaa049a77a3373310d315a6ec13f876/tools/ari-own-mailbox-witness/paired-guest/src)

## Reproduction

Use the pinned MVM source as `source`, SpiralCore as `spiralcore` and copy the workload directory to their sibling `paired-guest`. On Linux build the ordinary destination binary and its library test with `cargo build --locked --features object-reader-v1,large-object-fixture --bin spiralcore-durable-destination` and `cargo test --locked --features object-reader-v1,large-object-fixture --lib`. In MVM run `cargo test --locked -p mvm-agentd --bin mvm-guest-agent mailbox_reader` and `cargo test --locked -p mvm-hostd --lib mailbox_launch::object_pair`. The guest and workload suites passed 7 and 8 default controls and the pair suite passed 3. The additional explicit cross-package test passed once.

The cross-package test requires its own Linux mount namespace with private propagation. Mount an 8 MiB tmpfs named `spiralcore-worker-test` at `/run` with mode 0755 and a private 16 MiB tmpfs at `/tmp` with mode 1777. Supply absolute paths to the built SpiralCore library test binary in `SC_TEST_PRODUCER` and ordinary destination binary in `SC_TEST_WORKER`. Run the MVM guest-agent test executable with `--ignored --exact mailbox_reader::object_guest_tests::worker_component::worker_holds_computed_reply_across_indeterminate_submission --test-threads=1 --nocapture`. The test starts a native process and binds the normal application reader address inside those temporary mounts. The host side uses synthetic signed credentials and connected Unix sockets. The installed two-guest test must independently establish a genuine recipient receipt, successful readback, signed ACK and the exact repeat.
