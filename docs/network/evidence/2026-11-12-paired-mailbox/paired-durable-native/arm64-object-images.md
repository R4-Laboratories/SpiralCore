# ARM64 guest images for the installed object mailbox

The caller and receiver used in the Linux codec comparison now have statically linked AArch64 Linux executables for Apple Silicon guests. Wick built them with Rust 1.97.1 and the same `large-object-fixture,object-reader-v1` features as the x86-64 pair. The sealed caller image permits one worker and up to 16 Calls. The receiver permits one worker and up to eight Calls. Both keep the worker across the cold and warm phases. [Role source](https://github.com/R4-Laboratories/SpiralCore/commit/615d8ff98429b2339a069dcd0735c3df1a40af25) · [MVM guest source](https://github.com/Casey-allard/mvm/commit/c9d9fe87b27cd2e5fc64d2b1d9c3a31b522b2097)

The operator read both executables and the OCI entrypoint back from their ext4 images and matched their SHA-256 digests to the inputs. Each image’s embedded concurrency policy matched its intended role. All 56 runtime manifest entries verified. Starting with the same content-addressed guest archive in a second private home, the checked-in `prepare` executable independently assembled the initramfs, overlay, verification sidecar and SDK sidecars. Its complete runtime measurement matched the first preparation. [Binary, root image and runtime digests](arm64-object-images.json)

To reproduce, build the two established role binaries with `cargo zigbuild --locked --release --target aarch64-unknown-linux-musl --features large-object-fixture,object-reader-v1 --bins`. Run `prepare /absolute/path/to/pinned/mvm aarch64` under a fresh private MVM home with the source runtime acquisition mode. Pass the measured binaries and the archive’s AArch64 OCI entrypoint to the existing `image` command as roles `series-a` and `series-b`. The optional architecture argument selects the guest build target. Invoking `prepare` with the source path alone keeps its host-architecture default. [Build layout](../../../../../tools/ari-own-mailbox-witness/paired-native.md)

These are contributor-built test inputs. This preparation booted zero VMs. The selected Apple production registry path requires MVM’s admitted application pack and a verified upstream release of the guest runtime. Original Apple supervisor ownership, an installed transfer and all six measured streams remain distinct acceptance steps.
