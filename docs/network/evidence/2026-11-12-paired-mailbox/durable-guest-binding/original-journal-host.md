# Original mailbox helper custody and sealed source retries

On Linux x86-64, the canonical launch path retained B’s original mailbox helper process and authenticated the connected Unix socket against that process. A different live process bound to the same pathname was refused. The source sealer preserved a separately signed destination Send grant and the original sealed bytes across a simulated lost reply. Both a changed plaintext with the same message ID and a changed sender boot failed. [Recorded tests and hashes](original-journal-host.json)

A host launching an explicitly paired mailbox writes a private, synchronized ownership record before starting the helper. A second launch checks that record before touching the VM’s epoch secret. The record survives loss of the owner handle, an abrupt launcher exit and deletion of disposable VM state. An owner holding both the original process and record can clear it after collecting the process. If the owner is lost, the installation continues to refuse a new helper pending reconciliation. Ordinary mailbox launches continue to use Ari’s admitted posture, retention and guest boot checks.

The Linux `original_` selector passed 18 tests in 0.03 s. Six targeted behaviors are listed in the JSON. Other selected tests exercise existing MVM code or support the subprocess fixture. In the first test run the subprocess closed with a broken output pipe after the socket identity checks. The final harness retained stdout through actual process exit. The suite ran as host components without a booted MVM. No transfer, CPU or WAN measurements were taken. Earlier host journal byte and time measurements are recorded separately.
