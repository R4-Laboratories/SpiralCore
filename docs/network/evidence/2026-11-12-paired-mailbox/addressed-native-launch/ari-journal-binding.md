# Binding the paired guest route to Ari’s trusted-host journal

This integration targets MVM draft PR #5377 at `543efc7f94aa756c09785b38bdd024b6ba8199c7`. A and B each run a guest agent and an independently admitted mailbox helper. B’s journal is the authority for B’s trusted-host local-durable acceptance. The guest application can keep using the same SpiralCore frame over this endpoint. [Upstream proposal](https://github.com/tinylabscom/mvm/pull/5377)

| Edge | Implementation at the pinned draft | Paired-route work |
|---|---|---|
| A workload → A guest agent | The local-durable writer stages an outbox message. The shipped example selects its own mailbox. | Bind the authorized destination to the original intent, including the message ID. Staging alone leaves the intent pending. |
| A guest agent → A helper | The boot grant enables port 5257. The local helper seals the request and calls its own admission routine. The guest's local receipt check uses its enrolled authority, mailbox and epoch. | Enroll B's identity, verification key, destination epoch and sending permission under signed policy. Keep local and remote recipients unambiguous. |
| A helper → B helper | B already accepts the canonical capability and sealed envelope on its Unix service socket. The core exposes `send_local_receipted_frame` for the V2 local-durable tier. | Route the original sealed frame to the independently authorized B helper. Carry B’s receipt back unchanged. Recheck current authorization on retry. Same-host and WAN carriers must honor the same receipt contract. |
| B journal → B workload | B’s boot-bound reader supports Receive, delivers a lease and payload, and takes an explicit ACK. | B decodes the SpiralCore frame, checks exact length and bytes and processes the object before acknowledging the matching lease. Measure durable admission and application readback separately. |

The first two edges are visible in the [upstream writer](https://github.com/tinylabscom/mvm/blob/543efc7f94aa756c09785b38bdd024b6ba8199c7/crates/mvm-agentd/examples/mailbox_writer_client.rs), [guest receipt check](https://github.com/tinylabscom/mvm/blob/543efc7f94aa756c09785b38bdd024b6ba8199c7/crates/mvm-core/src/mailbox/frame.rs#L230-L249) and [helper's local admission call](https://github.com/tinylabscom/mvm/blob/543efc7f94aa756c09785b38bdd024b6ba8199c7/crates/mvm-hostd/src/mailbox_service/durable.rs#L344-L352). The last two use the [V2 sealed-frame sender](https://github.com/tinylabscom/mvm/blob/543efc7f94aa756c09785b38bdd024b6ba8199c7/crates/mvm-core/src/mailbox/frame.rs#L172-L214), [destination service](https://github.com/tinylabscom/mvm/blob/543efc7f94aa756c09785b38bdd024b6ba8199c7/crates/mvm-hostd/src/mailbox_service/durable.rs#L643-L679) and [workload reader and ACK](https://github.com/tinylabscom/mvm/blob/543efc7f94aa756c09785b38bdd024b6ba8199c7/crates/mvm-agentd/examples/mailbox_reader_client.rs).

Ari’s helper persists the original sealed capability and envelope for bounded same-ID retries. A duplicate at B can reproduce the original local-durable receipt while the authorization and retention checks hold. A transport outage still needs a paired witness that exercises both installed helpers and the return path. [Source retention](https://github.com/tinylabscom/mvm/blob/543efc7f94aa756c09785b38bdd024b6ba8199c7/crates/mvm-hostd/src/mailbox_service.rs#L146-L178) · [Destination duplicate handling and commit-before-signing](https://github.com/tinylabscom/mvm/blob/543efc7f94aa756c09785b38bdd024b6ba8199c7/crates/mvm-core/src/mailbox/journal.rs#L798-L865)

The first paired acceptance run must correlate A’s stable intent, B’s signed admission receipt, the leased delivery and B’s exact binary readback. Drop the receipt once and retry with the original sealed bytes to check that B returns the same signed acceptance. Record both directions, setup time, endpoint CPU, time to durable admission, and time through B’s verified readback and ACK. An altered payload under the same ID, a wrong destination, or a stale epoch must fail without clearing A’s pending record. The native deadline run used the earlier ephemeral endpoint. It measures failure recovery only. [Native evidence](paired-deadline-native.md)
