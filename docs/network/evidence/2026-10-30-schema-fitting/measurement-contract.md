# Frozen-schema versus trained-dictionary prototype

This bounded local experiment compares five existing/new Rust transfer paths on held-out exact bytes: raw, ordinary chunked zstd, conventional adaptive sparse/prefix using training bytes as its base, fitted schema, and a genuinely trained zstd dictionary. It is not a WAN, packet-total or energy result. The implementation baseline is `409a226357ec242bd5e8e5f72e4ae0b8fff155f1`; the final source/executable pins will be recorded before timing. There is no second old-source build or second acceptance campaign.

Ordinary zstd uses the existing per-chunk frames. The trained-dictionary path uses a whole frame with level3/window25/long-distance-matching/checksum/content-length settings matching the prefix profile. These are complete implemented paths; a difference against ordinary zstd does not isolate dictionary training from framing/window differences. The adaptive prefix baseline supplies the corresponding conventional whole-frame comparison using the same training corpus.

Training is exactly 512 deterministic, newline-terminated flat JSON records, using a separate seed/domain and disjoint sequence ranges from held-out records. Records contain twelve fields: type, site, node, seq, tick, temp, ok, note, status, revision, units and trace. Values include strings, numbers and booleans; no nested object is accidentally required for a normal record. Training sample boundaries, exact concatenated length and SHA-256 are frozen before timing. The schema fits only these samples. Zstd dictionary training uses precisely the same sample slices and fixed **8,192-byte dictionary budget**, with the typed artifact's header counted separately. Adaptive's verified base is the exact concatenation of those training samples.

There are four held-out families:

| Family | Purpose |
|---|---|
| Normal | Same field structure, unseen sequence/node/value bytes and distinct generator seed |
| Variants | Deterministic mix of whitespace/CRLF, field reorder, numeric exponent/string escapes and added/removed optional fields |
| Drift | New field set and longer differently distributed strings; no model update |
| Unrelated | Pseudorandom bytes with exactly the normal cell's length, including possible embedded zeros |

Each family is tested as one actual small record and as a batch made by appending whole records until at least **1,048,576 bytes**. Actual lengths and record counts are reported; there is no padding. Unrelated data preserves the corresponding normal target's length. The ten trials use different held-out seeds/record ranges, identical across arms for each pair. There is no held-out fitting, dictionary retraining, retrospective template update or case selection. Optional large-object correctness is deferred until the mandatory prototype is measured; no 16MiB performance claim is part of this campaign.

Fit/training runs once before the 400 target transfers. Each returns a serialized immutable artifact, so its CPU/elapsed figure is explicitly **fit/training plus serialization**; there is no invented separate serialization timing. Artifacts are stored once with their exact bytes, length and hash. The adaptive training corpus and both fitted artifacts are actually reused by the sender across **80 target transfers each**. The receipt reports this real reuse count and setup cost divided by those actual uses. Fresh parsed/context setup performed inside each codec's encode call stays inside transfer timing; reusable parsed codec contexts are not assumed.

The registered campaign is **10 trials × 4 families × 2 sizes × 5 arms = 400 target transfers**. Arm order is deterministically randomized per trial/family/size. Every arm uses a fresh receiver store and namespace with `ColdGraphPolicy::Disabled`. Adaptive, schema and dictionary arms first send their exact base/artifact through an ordinary raw transfer: **240 separately timed seeds** in total. Raw/zstd require no such seed. Seeding per destination and one-time sender fitting are separate costs. The experiment does not pretend a raw receiver needs a model to make setup costs equal.

Each target uses the real client, batch serializers and endpoint, including authenticated-context admission, decode, length/digest verification and durable publication. New client APIs are `transfer_schema_batched` and `transfer_zstd_dictionary_batched`, with artifact bytes, target, transfer ID, false exact-repeat probe and batch exchange callback. Their raw fallback is reported from `Stats.mode`; invalid artifacts are errors, not successful fallback. Adaptive may choose its best conventional encoding, but schema and dictionary arms do not silently substitute another learned codec. Artifact seeding is retained even when an attempted learned arm ultimately chooses raw.

After each seed and target acknowledgment, close/reopen the endpoint and compare its complete bytes with the original outside the transfer timer. Verification CPU/elapsed are separately recorded. Only newly created per-arm stores are removed after success; failures preserve the cache and all observations. Exactly 640 successful operation rows and 400 cleanup rows are expected. The five-arm comparison uses identical real input bytes per paired cell. Success requires exact recovery, complete counts and source/fixture identity; performance conclusions retain every slower or losing result.

CPU is single-process sender-plus-receiver CPU from preparation/encoding start through durable acknowledgment, counted once. The exchange and receiver-handler intervals are nested subsets; sender outside exchange is the total minus the nested exchange CPU. No intervals are added twice. Byte accounting includes both request and reply serialized envelopes, manifests/offers, data, requests and acknowledgments, plus the 16-byte equivalent reply timing fields. It is HTTP-body-equivalent accounting, not HTTP headers/TLS/IP/TCP/retransmissions. This is a local in-process serialized mechanism, not network send time.

Report per-family/size/arm medians and p95, paired comparisons, selected modes/fallbacks, total and directional body bytes, total/sender/receiver CPU, elapsed, model size, fit/training cost, and all seeds. Practical cold cost is measured seed plus target plus one-time fit/training; raw/zstd cold cost is target only. Amortized cost includes the actual 80 sends, their actual 80 destination seeds, and one fitting cost. Compound results use per-trial sums or the actual measured campaign sum as labelled, not a sum of unrelated medians. Fitting and fixture construction are not silently credited as eliminated application work. Owned artifact byte lengths are reported as retained model buffers; no RSS, peak-memory or energy claim is inferred.

All observations and failures are retained. There is one acceptance campaign, no favorable rerun, no outlier removal and no warm-up discard. No timing overlaps owned builds/tests/profilers or remote archive compression/upload. Builds reuse an existing target directory with `CARGO_INCREMENTAL=0` and a 4GiB free-space floor; successful worker stores are cleaned promptly. The shared local measurement pattern is reused without adding another statistical framework or independent-analyzer project.
