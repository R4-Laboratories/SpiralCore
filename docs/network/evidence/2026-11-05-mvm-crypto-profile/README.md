## First testable profile

Restrict the first probe to a mutually authenticated TLS-over-TCP endpoint pair on the tested Amazon Linux 2023 c6i.metal operating environment with Intel Xeon Platinum 8375C. The policy lists no vendor-affirmed operating environments. Use TLS 1.3, TLS_AES_128_GCM_SHA256, P-256 ECDHE, P-256 ECDSA/SHA-256 credentials and explicit peer admission. Disable tickets, resumption and early data for the first probe. Preserve the SpiralCore codec. This target exercises the transport and its trust decisions only. Linux/Firecracker guests, macOS/HVF, Windows client/gateway, QUIC and all canonical MVM inner services remain separately gated.

[CMVP #5314](https://csrc.nist.gov/projects/cryptographic-module-validation-program/certificate/5314) lists AWS-LC FIPS 3.1.0 static as Active at Level 1. Its [security policy](https://csrc.nist.gov/CSRC/media/projects/cryptographic-module-validation-program/documents/security-policies/140sp5314.pdf) identifies the tested environments and exact §11.1 build. It limits approved AES-GCM encryption to specified IV scenarios. Record the source and built module identity, operating environment, startup self-tests, approved services and key/entropy policy at both endpoints. Confirm the TLS record API and service indicators on the executed path. Quinn's Retry implementation uses a separate generic AES-GCM operation and needs an independent mapping. [Quinn Retry source](https://docs.rs/crate/quinn-proto/0.11.19/source/src/crypto/rustls.rs)

**Dependency blocker.** [Rustls 0.23.46](https://docs.rs/crate/rustls/0.23.46/source/Cargo.toml) requires aws-lc-rs 1.18 or newer. The default bundled path moved to AWS-LC FIPS 4.x in [aws-lc-rs 1.18.0](https://github.com/aws/aws-lc-rs/releases/tag/v1.18.0). It cannot be attributed to the exact 3.1.0 module in #5314. Resolve a maintained provider integration against a pinned §11.1-built module, or select a separately verified certificate and exact build. Rustls 0.23.42 with the earlier wrapper line and [1.17.1 system-library support](https://github.com/aws/aws-lc-rs/releases/tag/v1.17.1) is an API compatibility lead. A candidate release requires advisory and integration review.

## Admission and evidence still required

1. Anchor verification of the incoming bundle and plan in operator-selected trust policy. Require the authenticated plan and the selected deployment profile to agree before service keys or workers activate. Bind profile selection into future canonical handshakes where negotiation changes the cryptographic contract. Keep mailbox, FlowMux and owner access admissions distinct.
2. Exercise missing or wrong module, unsupported operating environment, integrity or self-test failure, and absent approved-service evidence. Refuse startup. Exercise peer identity, group, signature or cipher mismatch and fallback attempts. Refuse application data. Exercise lifecycle failures at both endpoints, including revocation, nonce and epoch transitions, and peer resume.
3. Record exact readback and length, both-direction wire bytes, setup and endpoint CPU, RSS and managed memory, and end-to-end latency through commit against an equally secured baseline. Add the production trust inventory, key lifecycle, build manifest/SBOM, tenant/cache isolation, compression leakage controls and platform/capacity evidence to the submission.
4. Confirm the customer’s contractual CUI baseline and control ownership with Ari. Apply the [NIST SP 800-171](https://csrc.nist.gov/pubs/sp/800/171/r3/final) baseline and parameters required by the contract.

Profile implementation, approved-mode execution, native/WAN results under this profile, customer compliance and upstream acceptance are open.
