# Focused debug-profile deadline diagnosis

The original 9ff7b247 debug lib run is retained remotely as `live-lib.txt`: 76 passed, one failed at the late-retry fixture's expected `ServiceError::Unavailable` assertion. Its same-source release run passed. Neither result explains the other profile's behavior by itself.

One focused execution of the original existing debug binary reproduced the failure without Cargo or source changes: exit 101, 0/1 passed. `late-write-debug-focused-binary.sha256` pins that executable; `late-write-debug-focused.txt` and `.exit` retain execution. The fresh `late-call-retry-write-deadline.json` records actual outcome `canonical session: Service(Expired)`, completed before the watchdog, one send invocation, one complete Call frame, null retry-start time, zero write stalls and zero completed application Calls. Accepted bytes are exactly the handshake plus original frame (4665); no partial retry bytes were accepted. Reentry added no read/write calls. This failure therefore never exercised the fixture's intended partial retry-write phase.

The source issues a legitimate signed 900ms lifetime, then schedules the explicit request 600ms after completion of the initial Call send. Initial authentication/registration and the retry's fresh authenticated registration/remaining-time checks also consume the original lifetime. In the observed debug run, expiry wins before the second invocation. The exact internal substep consuming the remaining time is not independently timed; the counters establish the pre-invocation result. This is consistent with correct expiry refusal and does not demonstrate a refreshed or overlong writer deadline.

Recommended fixture correction, pending lead approval: request the retry from the existing initial-complete-frame event, without the artificial 600ms delay. Retain the original 900ms signed TTL, parent 2s timeout, 1.5s watchdog, typed write failure, two-invocation requirement, exact original identity and exact partial-byte/stall assertions. The blocked retry still must terminate at the original deadline; an incorrectly refreshed 2s writer would exceed the watchdog. No timeout increase, assertion relaxation or product fix is proposed. No test/source edit was made during this diagnosis. The original failure and focused confirmation remain failures, not acceptance receipts.
