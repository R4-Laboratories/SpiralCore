# Matched strict-transfer release comparison

Registered before this comparison executes: unchanged `examples/broker_objects.rs`, twelve local TCP cells, three deterministic 1 MiB workload trials each for whole-object zstd and Combined, paired old/current order alternated on trial one. Baseline protected source `960e73c5`, binary `04a57c32154acad6dbc3754775039aad80cab632e77f9d50dce9965d52ad8d35`; current production at `07e1bf83`, normal release binary `fe7937f2fb348ff0a3c517cf856f2ad132883346a8aa05020e6dbd0e1d62b6d7`. Subsequent fixture-only fixes must be separately pinned; they cannot be described as this executed binary's commit.

The normal guest path is still strict: this comparison qualifies receiver-preamble/deadline/report compatibility and existing byte savings. It does not measure the opt-in public consumer's channel/Idle overhead or recovery speed, native MVM, WAN, energy, or send-only time. Functional recovery rows separately record actual bytes and process CPU/wall domains. Do not relabel them as comparative performance.

Each cell is a fresh process, eight common target byte strings in one persistent session with checkpoint/schema setup included, independent exact object reopen checks. Aggregate process CPU is measured once, endpoint thread CPU separately; overlapping campaign process intervals must not be summed. Count both logical directions including canonical ciphertext, framing, initial status and setup; no TCP/IP headers/retransmissions. Include setup, verified transfer/readback and cleanup; retained file records define each domain. RawMixed is an optional raw codec with the same exact warm cache, not a cacheless raw baseline.

Release goals: zero fidelity loss, exact stream-counter agreement, no unexplained byte increase on common targets, bounded existing memory/disk ceilings. Time/CPU before/after and per-workload losses must be published even when noisy or negative. Three paired exploratory trials are not the thirty randomized WAN acceptance trials or evidence for tail latency. Successful owned payload stores are removed only after evidence is flushed; failed stores remain for diagnosis.
