# Compressed schema and prepared codec reuse: registered local experiment

SC-OPT-012 compares eight Rust paths on repeated **distinct** targets sent to one persistent receiver per arm/session: raw, ordinary chunked zstd, conventional adaptive using the training corpus, schema V1, schema+zstd, prepared schema+zstd, trained zstd dictionary, and prepared trained dictionary. Baseline is `e0a29bc`; final source/executable/fixture hashes will be frozen before timing. This is one bounded local serialized durable-transfer campaign, not a WAN or energy measurement.

The existing `schema_fitting` example shares its generator, training records, serializer channel and distribution helpers with a support module and new `reuse-plan`, `reuse-run`, `reuse-summarize` commands. Training remains the identical 512 records and dictionary budget 8,192 bytes. Schema fitting and dictionary training each run once per campaign; immutable artifacts, their serialized lengths and fitting/training-plus-serialization CPU/elapsed are retained. No held-out refitting occurs.

There are ten paired trials, two sizes and eight arms, each with ten target sends: **1,600 targets**. Each session follows normal ×4, lexical/field variants ×2, drift ×2, unrelated binary ×2. The private fixture index is `trial*10+position`, in 0–99; the generator is unchanged and regression tests bind historical indexes 0–9 to their previous frozen identities. Small targets are actual single records; batches append whole records to at least 1,048,576 bytes. Binary controls retain the corresponding normal object's length. There is no padding. The plan records every exact target length, record count, digest, family and position. All ten object IDs must differ within a session, and paired arms receive identical bytes. Exact-repeat probes are disabled.

Arm order is deterministically randomized for each trial/size. Each arm/session has a newly created receiver store and namespace, using `ColdGraphPolicy::Disabled`, and retains that Endpoint for all ten sends. Raw/zstd need no seed. The six dependent arms seed their actual training corpus or artifact once, through the ordinary raw path: **120 seed transfers**. The two prepared arms create their sender encoder once per session: **40 preparation measurements**. Preparation CPU, elapsed, retained bytes and resource charge are recorded separately from target sends. Unprepared APIs recreate their required codec state inside each target's measured call.

Receiver codec retention is **disabled for the six baseline arms** and **enabled for the two prepared arms**, before seeding. The prepared comparison therefore measures combined sender and receiver preparation/reuse. Separate sender-outside-exchange and receiver CPU are reported; a combined difference is not attributed solely to sender reuse. Cache snapshots before and after each operation expose actual hits, misses, evictions, entries and resident bytes. Cache counters are observations, not presumed hits; raw fallback may perform no fitted decoding. The production cache's bounded entry/resource rules apply unchanged.

Each operation uses the real client and serialized request/reply batches, authenticated-context admission, exact length/digest verification and durable publication. Receiver `read_object` compares the full original bytes outside each timer **without reopening or clearing codec state**. At session end, close/reopen once and reverify the seed (when present) and all ten targets, again outside transfer timing, before removing only that newly created store. Successful completion requires **1,720 exact immediate comparisons, 1,720 exact reopened comparisons and 160 successful store cleanups**. Failure observations and their stores are retained; no failed row disappears behind cleanup.

CPU covers preparation/encoding start through durable acknowledgment, counting sender plus receiver once in the same process. Exchange and receiver measurements are nested subsets. Sender CPU is total minus exchange CPU; subset intervals are never added again. Request and response body bytes include batch framing, requests/acks and 16-byte equivalent reply timing metrics. HTTP/TLS/IP/TCP bytes, retransmissions and real network send time are outside this local experiment. Fixture generation, evidence serialization and exact verification are outside target timing and are not claimed as eliminated application work.

Report per-size/arm/position and per-family medians/p95 for body bytes, total/sender/receiver CPU and durable elapsed, raw fallbacks and cache behavior. Separate the first target from positions 1–9; this is a mixed-family sequence, so that aggregate does not isolate cache warm-up from content. Each session's cumulative ten-target costs include its actual seed and preparation. Campaign totals include all sessions plus one fit per artifact family, with actual reuse counts stated. For comparing arms independently, each fitted arm is charged one fit of its required artifact; those counterfactual arm totals must not be summed as the actual experiment's global fit count. No receiver seed is silently omitted or re-amortized beyond the ten observed sends. Use per-session sums before computing distributions, not sums of unrelated medians.

Schema+zstd is an exact compressed schema stream; it may still lose and its attempted encoding cost remains charged when raw wins. Ordinary zstd uses per-chunk framing while dictionary/schema compressed paths use their implemented whole-stream settings. Comparisons concern complete paths, not a claim that one isolated feature explains all differences. The frozen schema/raw artifact profiles remain controls. Artifacts and prepared-state byte/resource counts are not peak-memory or RSS measurements.

There is one registered run after qualification/source freeze, no favorable rerun, no outlier exclusion and no discarded warm-up. Every row and error is retained. No timing overlaps owned builds/tests/profilers/uploads/compression. Existing build directories are reused with `CARGO_INCREMENTAL=0` and a 4 GiB free-space floor. Stores are cleaned after each successful ten-target session, keeping receiver disk use bounded to that session. Larger-object, WAN and energy qualification remain unmeasured here.
