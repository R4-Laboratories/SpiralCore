The original `verify-owner.sh` assumed an artifact's checked-out commit equals the PR head. The four original ZIPs actually report tested merge `dd8362d0f7265849653f58c53c6d5bfd185f7a46`, while the run API reports reviewed PR head `64d93fed72fdac6784d99e6e1a258052bba605f6`. The original script's standalone `[[...]]` checks were false, but local `/bin/bash` 3.2.57 continued despite `set -e`. A scoped `bash -x` execution of the unmodified script reproduces four false commit comparisons followed by its PASS output. A separate tiny control captures equality status1 followed by continuation under errexit. No variables, source objects or artifact bytes were corrupted; the verifier relied on incompatible shell failure semantics.

`verify-owner-original-unaccepted.sh` preserves the original script byte-for-byte. **The PASS conclusions in `owner-verification.txt`, `owner-verification-rerun.txt` and `original-unaccepted-trace.txt` are unaccepted.** Their original raw contents and exit receipts remain retained; none is used as qualification. `bash-conditional-diagnosis.txt` isolates the shell behavior without environment or secret contents.

The corrected verifier uses explicit failure branches for comparisons, validates run/head/base identities, and checks immutable GitHub commit API records. `tested-merge-commit.json` identifies parents `[7c220cc841fa441df176a58cb24aeecd4d4d5fad, 64d93fed72fdac6784d99e6e1a258052bba605f6]`. Both tested-merge and reviewed-head API trees equal `3d478a93c3366997913bc0d44f2c5c8e3440d98b`, which is also the locally resolved reviewed-head tree. Each ZIP must name the tested merge, not the PR head. The original ZIP/API digests, twenty recorded compiled-source pins, exact 4+9/4+10 native row counts and Clippy completion are rechecked without running CI or product tests again.

Accepted receipt: `owner-verification-corrected.txt`, exit0 in `owner-verification-corrected.exit`. It names tested merge, reviewed head and shared tree separately for all four rows. Controls in `control-wrong-commit.*` and `control-wrong-digest.*` each exit1 with the expected explicit refusal. These controls modify only disposable verifier copies under `/tmp/spiral-owner-verifier-controls.*`; original archives, API records and tested source are unchanged.
