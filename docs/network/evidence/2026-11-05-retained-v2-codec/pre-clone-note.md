# Author note: validate private reverse input before cloning

2026-11-04. Narrow AUTHOR finding/proposed TDD follow-up, not an independent review. No source change or new Cargo job was made for this note. The exact qualified ten-test/scoped-Clippy snapshot remains frozen in this directory.

Current codec `retained_transfer.rs` SHA374aeeacc23a60a6dfd531797619109f6996b3a881251a4c53063904ffd9a426: `CatalogV2::reverse_source` checks the installation identity, then clones records (v1 branch) or the entries vector (v2 branch), and only the destination encoder checks total rows/origin and record shape. `decode` and `from_v1` currently produce bounded values, so the executed ten tests and these producer paths are unaffected. A directly built private CatalogV2 with >16 rows or an oversized record path can, however, allocate its clone before the final encode returns Err. This is an input-order/resource-contract issue, not a demonstrated grant/admission bypass or native exploit.

Minimal proposed change: extract one nonallocating structural validator from encode (key/generation/mode, <=16 rows, origin installation/profile/generation, record.valid and current duplicate tuple/session/path/state rules). Call it from encode before allocation and reverse_source before either cloning branch. Preserve all successful canonical bytes, reverse proof and v1 semantics. No new quota, capacity, wire field, I/O, scope or permission.

Focused RED proposal before product fix: a cfg(test)-only hook immediately at each actual reverse cloning boundary, armed in a thread-local test scope. With an explicitly oversized private format value, reverse_source must return Err WITHOUT visiting that boundary. The existing source reaches it, giving a genuine ordering failure; a valid control must demonstrate that the hook is actually reached. Test both oversized row count and oversized path, and both v1/v2 reverse branches. Label this a clone-boundary ordering observation, not an allocator/RSS measurement, natural exploit or native proof. No public hook/constructor/authority or global allocator is needed. Preserve this first snapshot's successful ten tests and initial clone_on_copy lint failure separately, then run selected regressions/scoped Clippy only after an explicit lane loan.

B2 activation and its requested-byte/capacity model must not assume this ordering guard already exists. Broader native/transaction/restart proof remains open.
