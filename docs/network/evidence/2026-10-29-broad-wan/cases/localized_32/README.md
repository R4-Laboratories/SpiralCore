# broad16-localized_32: five-shard evidence custody

This packet preserves the first completed broad16 case at source
`9dce4c57d1f41cef7365b297cd690849afce34e7`: five distinct, successful first-attempt
GitHub runs, 30 paired trials across four arms, and 240 successful seed/transfer
receipts. Each shard's canonical local plan matches the downloaded plan byte for
byte. The reopened verification receipts compare 48 publications per shard exactly,
805,306,368 bytes per shard, outside measured transfer timing.

`aggregate.json` contains the case's numerical analysis. Independent numerical review
and packet replay have separate receipts and limits; a review process failure is not
a measurement failure. The intentionally empty historical v1 review output is retained
under `history/` and is not a passing review. Its structured correction receipt records
the capture-row task-projection mismatch and RED-to-GREEN repair. The successor
`independent-review-v2.json` passes all 240 receipts and the author's statistics.
`common/independent-checker/` preserves its Rust source, locked dependencies, fixtures,
methods and qualification history without the executable or diagnostic output.

Each `shard-N/remote/` directory retains the original readable rows, plan, summary,
packet-accounting/lifecycle receipts, tcpdump counters, route/offload state, sender
identities, authenticated build-reuse proofs and fresh runner capture qualification.
The parent directory retains receiver verification, publication hashes, cleanup,
run/artifact API identities and archive custody. `common/` holds the frozen receiver
compiler, CPU, features and executable identities. Its original pre-run `NOT_RUN`
label is historical freeze metadata; completed per-shard receipts provide run status.

For each run, fresh authenticated GitHub API responses established the exact repository,
workflow, source, successful attempt one and exactly one expected measurement artifact.
The selected ZIP's actual SHA-256 and byte count match the API digest and size. All
56 ZIP members per shard were streamed and hashed against every existing downloaded
file: 280 of 280 exact matches. `evidence-remote-files.sha256` preserves that complete
inventory, including files omitted from this Git packet.

The original ZIPs and four PCAP files per shard remain under the absolute local
paths in `local-raw-custody.json`. They are hash-bound here but omitted from Git.
The small capture-qualification client-finished and fixture-server PID marker files
also remain local and are hash-bound in the complete remote inventory. No executable,
capability secret or diagnostic stdout/stderr is included in this packet.

Each receiver cache inventory has 50 files: 48 `.object` publications, the
`.spiralcore-profile-v1` marker and the empty `.owner` lock file. The original checksum
verification reported all 50 files OK. These are not 50 measured publications. The
synthetic caches were removed only after exact reopening and hashing; those recorded
cleanup actions are distinct from hosted artifact cleanup.

`hosted-artifact-custody.json` names only the five owned measurement artifacts, totaling
105,412,440 ZIP bytes. No hosted artifact has been deleted by this packaging step.
Deletion remains contingent on parent review and committed preservation, with local
raw ZIP/PCAP evidence retained. The producer artifact ID 12931876271 must remain
available for later cases and is explicitly excluded from this cleanup list.

Measurement scope remains the selected GitHub-runner-to-Cloudflare TCP443 leg for
captured IP bytes, not both legs or physical-link bytes. Sender CPU plus receiver
handler CPU is computation accounting, not energy; elapsed transfer time already
includes computation. Fixture generation and reopened verification are separate.
Scientific claims must retain the individual aggregate/review limitations.
