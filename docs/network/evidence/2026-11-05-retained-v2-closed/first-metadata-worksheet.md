This is a source worksheet, not activated model or whole RSS proof. The existing 1 MiB fixed metadata reservation and quotas are unchanged.

* The new fixed observer owns one `TransferIntent` (768 encoded bytes; in-memory size guarded below), one original `TransferFiles` (10 Option<File> slots), one fixed observed `TransferFiles`, one Mutex and one Arc allocation. The transaction separately holds the bounded acquisition box while bootstrapping. No catalog is read into a Vec before metadata funding.
* Before funding, the original directory, owner, holders and immutable intent/state descriptors are armed in fixed slots. The fixed intent read is 768 bytes; fixed state read is 176 bytes. `bounded_hash` uses ONE 8192-byte stack scratch and SHA state per sequential call. It streams catalog hashing rather than retaining another 69,752-byte heap buffer. These fixed read-only constructor/stack terms are not zero and remain in the qualified native stack/model domain.
* After funding, raw actual catalog, encoded target catalog and reverse-source reconstruction can overlap (3 × 69,752 bytes = 209,256 bytes), exactly the corrected three-raw-buffer assumption in the B1 worksheet. No fourth raw catalog buffer is introduced by the observer. Codec decoded membership/strings remain inside that worksheet's separately assigned terms. The target decoded Vec dies when `resume` returns; the retained observer stores only the fixed intent and File slots.
* Additional fixed observer/transaction descriptors, Mutex/Arc/box/layout fields receive a 16 KiB provisional metadata envelope, to be enforced by ABI/size tests before numeric acceptance. This consumes 16,384 bytes of the previously recorded 118,424-byte corrected margin, leaving 102,040 bytes. This is an assignment pending independent review, not a cap raise or a claim that allocator/kernel descriptors are Rust heap bytes.
* The original closed ledger, all row R+K charges and 1 MiB metadata charge move as actual objects. The observer never creates quota. All failures retain original armed custody. No ordinary reservation can use the CLOSED observation.
* Native allocator, kernel FD backing, pthread/TLS/cache and RSS terms keep their existing explicit qualification gates; this worksheet does not close them.
