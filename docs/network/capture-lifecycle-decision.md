## Authorized new controller contract

Implement `spiralcore-capture-control` as a native Rust experiment utility using current crate dependencies. The workflow delegates process lifecycle to it. The existing packet parser remains the sole packet-accounting implementation and accepts a new optional lifecycle receipt; new campaigns must provide it. Legacy invocations preserve their current behavior and historical incomplete result.

1. **Fresh bounded files.** Require a fresh controller state directory within the existing result directory, exclusive output creation, selected local/remote IPs and interface, snaplen 96, PCAP maximum 256 MiB and control-log maximum 1 MiB. Never serialize environment variables or the capability token. The benchmark receives its existing environment.
2. **Record the actual tools.** Preserve tcpdump/libpcap version output, executable identity where accessible, exact flags and interface, controller/source identity, UTC/monotonic phase boundaries, child PIDs and exit outcomes. Workflow retains route, pinned-IP, offload and compiler evidence separately.
3. **Own the capture process.** Use a fixed `sudo -n`/`exec` shim that reports the actual tcpdump PID through a fresh private file. Arguments are separate values, never interpolated shell code. Signal only this owned PID, and reap the tracked sudo child. Refuse an invalid PID. A permission or launch failure is a failed setup, not successful capture.
4. **Configure buffering explicitly.** Use `--immediate-mode -B 4096 -U -s 96 --time-stamp-precision=nano`, the selected interface and the exact selected TCP443 filter. Immediate mode is a mitigation for unread batches, not a completeness guarantee. Record the changed capture configuration for comparison boundaries.
5. **Premeasurement readiness.** Within ten seconds, observe tcpdump's filter-ready listening message, live owned process and complete PCAP header. Obtain two complete SIGUSR1 counter snapshots at least 500 ms apart. Both must have captured=received, zero reported drops and unchanged counters/file extent. Only then start the sender. A startup discrepancy aborts before measured work; it is never subtracted from later counters.
6. **No controller polling within timed client work.** The controller waits for the benchmark child. It records the actual child result and then begins post-client capture handling. SIGUSR1 sampling happens before/after the campaign, not within operation timings.
7. **Bounded post-client quiescence.** For at most ten seconds, request complete counter snapshots at 500 ms spacing. Require three consecutive equal snapshots with captured=received, drops=0 and stable PCAP extent, spanning at least one second. SIGUSR2 may flush userspace output before sampling, but is never described as a kernel drain. An unstable stream or timeout marks the lifecycle incomplete. This is bounded quiescence evidence, not proof that future retransmissions or network activity cannot occur.
8. **Stop and reap.** Send SIGINT to the owned process, reap within five seconds and require successful exit. A bounded SIGKILL cleanup is allowed only after failure and must be recorded as incomplete. Do not hide signal/wait errors. Record final complete counters separately from earlier snapshots, and write a canonical final three-counter text file for the existing parser. Do not concatenate repeated SIGUSR1 blocks and ask the parser to pick one.
9. **Final accounting remains authoritative.** PCAP must end at a complete record boundary, its count must equal final captured, final captured must equal final received, and kernel drops must be zero. Preserve all existing SYN ownership, ambiguity, application-body coverage and partition checks. A lifecycle failure must force `capture_complete=false` even if the packet totals happen to match. A race between the last snapshot and SIGINT remains possible; final disagreement fails closed.

The controller receipt must distinguish `ready`, `preflight_qualified`, `client_exited`, `quiescence_qualified`, `capture_reaped`, `final_stats_complete` and errors. It retains every bounded pre/post snapshot with its phase and observed offsets. This makes a future mismatch diagnosable without accepting it. Raw stderr is diagnostic; compact parsed snapshots and final outcomes are the durable scientific evidence.

## Conventional delta feasibility

Local read-only availability check found `/usr/bin/rsync` (openrsync protocol 29, rsync 2.6.9 compatible), but no `xdelta3`, `xdelta` or `vcdiff` executable. The current transfer lock contains zstd 0.13 and zstd-sys based on zstd 1.5.7; no VCDIFF dependency exists.

The current `Offer` already carries final target length/ObjectId and an optional verified base ObjectId for sparse mode. A conventional delta codec can use the same authenticated HTTPS batching, sequence checking, namespace authorization, bounded base loading and final durable publication. It needs a distinct declared mode or explicitly versioned codec profile, not relabeling sparse bytes. Preserve wrong-base rejection, encoded/output/work bounds, complete-frame and complete-stream checks, exact target hash and no automatic fallback under a reused transfer identity.

VCDIFF is a standardized portable delta format, but format support does not choose an encoder or establish a resource-safe decoder. [RFC 3284](https://www.rfc-editor.org/rfc/rfc3284). Xdelta provides a mature C encoder/decoder, while open-vcdiff provides a C++ implementation; both introduce an additional third-party implementation and build/CPU-accounting boundary. [Xdelta primary repository](https://github.com/jmacd/xdelta), [open-vcdiff primary repository](https://github.com/google/open-vcdiff). The inspected pure-Rust vcdiff-utils repository exposes parsing, decoding and instruction-writing components; that is not qualification of a competitive general-purpose encoder. [vcdiff-utils](https://github.com/ThinkingJoules/vcdiff-utils).

No tool was installed and no VCDIFF source was imported. If later selected, pin exact source/license/compiler/configuration, disable unneeded secondary/armor features, independently cross-decode known patches, and bound malformed COPY/window/varint/output work. Child-process codecs require child CPU and temporary-file costs inside the measured boundary; parent-process CPU alone is insufficient.

The architecture agent is investigating the already present zstd dictionary/prefix path as the first conventional base-aware control. That avoids selecting an unqualified VCDIFF implementation merely to obtain a control quickly. Its precise codec profile, window/base limits, readiness fairness and named provenance must be explicit. A VCDIFF arm can follow after separate qualification; this investigation makes no claim that either has already run through the shared WAN path.
