# Unix directory ownership for installed object storage

**Architecture approved by the project owner on 13 November 2026.** Give an already admitted Linux or macOS installed codec session its original store directory and retain its original writer lock through retirement. Preserve SpiralCore v1 message bytes, object identity, per-operation authority and both quota decisions. The initial change leaves the implementation and behavior of all existing Path constructors, Unix Path storage and Windows storage intact. The new route is for installed SmallV1 only. General-profile storage, full MVM scale, other resource envelopes and fleet capacity remain open.

**Observed defect.** On macOS the installed controller creates and opens its private child relative to the original parent, then synthesizes `/proc/self/fd/N/flow-…` for the Path endpoint and its cleanup. The host has no usable child lookup through that prefix. The close and poison relinked custody diagnostics both report `NotFound`, OS error 2, before the prepared-reader hook. That observation identifies the failed preparation, without attributing it to an individual syscall from a trace. The separate broker and sideband fixtures each passed. Direct control lookups of a known child through both procfs and devfs prefixes also returned ENOENT. Neither a pathname reconstructed from the kernel nor an ambient absolute path is sufficient for original-directory custody.

## 1. Public storage and custody interface

Proposed Unix-only local types and functions (names denote the review surface, not existing APIs):

- `OwnedStorePolicy::small_v1(limits: &Limits, funded_entry_visits: u16, lanes: OwnedLaneNamespaces) -> Result<OwnedStorePolicy>`. The proposed closed `OwnedLaneNamespaces` input is `One(Id)` or `Two(Id, Id)`; the two IDs must be distinct. The installed caller derives them from the currently authenticated lane Contexts using the existing `Context::namespace()`. Capture freezes these actual IDs on the lease before any scan or create. The codec requires membership for every namespace locator, including ordered lookups, quota traversal and retirement. An unlisted directory is counted and refused before descent. Filenames, prior disk contents and counts cannot enroll a lane. Membership never replaces fresh per-operation authority. SmallV1 checks and checked arithmetic apply at policy construction and endpoint open.

**Phase 1 — capture and publish custody to the original permit.** `OwnedStoreLease::capture(parent: Arc<File>, leaf: &OsStr, child: Arc<File>, policy: OwnedStorePolicy) -> Result<OwnedStoreLease>` reads metadata on the held descriptors and on the validated single generated component relative to the original parent. It checks the private original child, matching named identity, UID, mode and mount premise. It performs no directory scan, create, lock, unlink, profile write or stage operation. The MVM permit already holds the parent/leaf/child tuple and its debit from original creation. On capture success MVM attaches a clone to that permit **before** invoking endpoint open. The raw tuple remains available even if capture fails. Lease clones share the same inner state and FDs.

**Phase 2 — claim one endpoint and acquire original exclusion in the retained lease.** `ObjectEndpoint::open_at_with_resource_profile(lease: &OwnedStoreLease, limits: Limits, authority: A, profile: NegotiatedProfile, resources: ResourceProfile) -> Result<ObjectEndpoint<A>>` verifies the caller/profile and takes a single-use endpoint claim. Recheck the named child before effects. Open or create .owner under that child with the existing exclusive-creation and bounded lock semantics. Use a preallocated slot in the permit-backed inner state: install the opened file directly into that slot before any next fallible validation, acquire the lock on that same stored FD, and retain the actual lock before further checks, profile initialization or recovery. Failure after open retains the FD and records whether the lock was attained. Failure after lock retains the **locked** FD. Validate the named inode against that FD and repeat the marker checks before allowing work. Once storage acquisition has started, error or unwind marks the claim quarantined. Other clones cannot retry the open, unlink or reacquire the marker, create a second endpoint, or release the debit. The original owner resolves quarantine; a file opened without achieving lock is never deemed exclusive. Success gives the endpoint one lease clone. The original owner lock is shared by custody, not duplicated. OrderedObjectEndpoint::new uses this endpoint unchanged. A later, separately admitted reopen after original process exit must acquire genuine exclusion on the pre-existing named original.
- `OwnedStoreLease::retire_contents(&mut self) -> Result<()>` requires exclusive ownership of the lease inner after the original end of admission and reader/endpoint drain (e.g. `Arc::get_mut`); any other live endpoint/custody clone makes retirement fail closed. It holds the same locked file throughout, including after unlink of the .owner name. The MVM permit still owns the lease through final parent-relative rmdir, parent fsync and checked absence. Partial unlink, fsync error or uncertain worker join retains state, original descriptors, exclusion and debit. After .owner was unlinked but terminal cleanup failed, keep the old **locked original inode**, quarantine and refuse fresh opens on that installed leaf. A retry can advance only the recorded original cleanup phase under the same controller and named-child identity. Do not synthesize authority from finding an empty directory.

## 2. Finite entry, descriptor and heap budgets

Installed prepare currently constructs one PinnedScopePolicy, one admitted TLS pair/role and its directions. Freeze at most two sanctioned lane namespaces per owned root in this first slice. Enforce their actual session-derived namespace IDs before namespace creation and during retirement; if the real mapping admits a third namespace, refuse this profile. For the default SmallV1 limits, budget **101 non-pseudoentries per complete walk**: two root markers (.owner and .spiralcore-profile-v1), one profile staging allowance, two lane directories, 64 published files total, and 32 residual object-stage slots. The 32 are an explicit local restart allowance sized to max_states, not a claim that that protocol limit caps abandoned filesystem records. Live publication has one active state. Empty lane directories, unknown stems, arbitrary dotfiles, abandoned/recognized stages and other unknown entries all consume the *same* total. The fixed count uses checked arithmetic `2 + 1 + 2 + limits.max_publications + limits.max_states`. Both lane directories combined share the 64 publication and 32 stage allowances. Lower negotiated limits lower the bound. The installed resource owner reserves this finite work allowance per original engine in `reserve_installed_profile`, stores it on the original permit and supplies it at prepare. For L allowed processed entries the owner funds L+1 non-pseudoentry observations per walk, including a single overflow lookahead. Default L=101, funding=102. Reject insufficient funding. Store L and the exact allowed namespace IDs on the lease. No MVM wire field, negotiated version or new right to access another namespace is introduced.

Each top-level traversal starts **one** remaining counter shared by root and child iterators. Skip only kernel `.` and `..`. Inspect at most the permitted number of names and the single next entry required to detect overflow. Charge before any classification, open, stat or effect; abort with `Error::Limit` on that lookahead. Never descend beyond root → namespace → leaf. Track at most two namespace IDs. Keep ordered metadata vectors separately capped by the original publication limit; stream all other enumeration. Audit any helper capable of internally collecting a directory into a Vec. Preflight selection, candidate identities, total entries and staged increment before destructive recovery/eviction or publication. If a create would exceed the funded count, refuse before creating the stage or namespace and keep accepted data intact. Initial over-budget retirement refuses before any deletion. Revalidate the named entries on the effect pass. Constrain all multi-pass algorithms: two whole passes for a validate/apply operation if the backend supports mutation without losing iterator progress; otherwise validate then perform at most L unlink steps with one fresh bounded pass per step plus one final verification, with strict progress each step. At default L=101 this permits at most 103 bounded walks for one cleanup attempt, including the initial validation and final walk. The conservative upper bound is 103 × 102 = 10,506 non-pseudoentry observations per attempt; no automatic retry after failure. Refund only at verified terminal retirement. Return to quarantine on uncertainty. Begin and Commit continue making independent full quota decisions; over-budget is never a signal to drop publications to obtain space.

Count the shared parent once per controller, then **two persistent FDs per prepared store** (original child and original .owner). Arc clones duplicate neither. Design the storage operation on each serialized endpoint for at most **four transient FDs**: root directory iterator, namespace lookup FD, independently opened namespace iterator, and one object/marker/stage verification FD. Close a stage before the independent final-file readback, avoid nesting directory walks during publication, and run retirement after endpoint drain. Implementation must verify all error/recovery branches fit this ceiling; no implicit per-entry FD clone. Local reservation therefore must cover parent + 6 × simultaneously admitted stores, in addition to unrelated carrier, peer, audit, sender and reader FDs. Multiple owner threads require their own admitted counts. The two live iterators have their own bounded directory buffers and at most two current component names plus the one checked file header. Before activation, derive the buffers' maximum allocatable size from the pinned rustix Linux backend and the supported Darwin libc/FD filesystem implementation, include name and metadata vector capacities, allocator rounding and Rust stack. If a platform cannot provide a defensible bound under its supported mount profile, keep this route disabled there until a bounded iterator implementation or an enforceable owner memory ceiling covers it. An observed RSS peak alone cannot discharge this resource debit.

## 3. Filesystem and lifecycle rules

1. Use rustix relative operations on a held FD. Candidate opens on both platforms use NOFOLLOW | NONBLOCK | CLOEXEC before fstat, plus DIRECTORY for directories and correct RO/RW/create flags. This makes an unexpected FIFO refuse promptly. Validate effective UID, private mode, type, regular file nlink=1 and actual device/inode. Named .owner and namespace entries must still identify their original held objects. Validate each exact single component, reject separators/parent/absolute names, never silently translate invalid bytes. Exact namespace syntax is 64 lowercase hex; unknown-stem .object regular files still count toward the existing byte quota where eligible but unknown data does not become removable by grammar alone.
2. For iteration explicitly `openat(held, ".", RDONLY | DIRECTORY | NOFOLLOW | NONBLOCK | CLOEXEC)`, validate the returned FD, then `rustix::fs::Dir::new(owned_fd)`. A dup shares offset; libc Dir::read_from can represent open-dot ENOENT as empty. Even after Dir::new, pinned rustix Linux raw getdents can map ENOENT to end-of-directory. Verify held inode, nonzero link count, and original parent-to-named-child identity before accepting an empty/successful scan and after traversal. Never treat lookup, permission or fsync failure as evidence of emptiness. Reject device changes (even across lookup/open) before reading or removing contents. A same-device bind mount is not exposed by st_dev alone. Require an original owner-controlled private mount tree with no nested/substitutable mounts on both platforms; use native mount identity checks if the provider supports them. Refuse if the provider cannot establish the mount premise. Same-UID independent mutation/mount replacement remains outside the writer-exclusion guarantee; statat plus unlinkat is not atomic compare-and-delete.
3. Implement the FD branch for **every** open_config/profile check/recovery, open_publication/find_base/disk_usage, ordered_cache_scan/read/admit/evict, stage/create/publish/readback, cleanup and sync. Use validated concrete relative locators in publication metadata. Reopen the exact object under its verified namespace; perform existing fresh metadata, length, digest and exact-body checks. Preserve original grant and holder checks, active pins, single/multiple eviction preflight, and separate Begin and Commit arithmetic. Use exclusive creates and sync stage → renameat → fsync namespace/root before success. Remove error stages only under original identity; no raw path fallback. Retire recognizes original namespace, verified publication IDs and privately created stages under existing generated name grammars (`.stage-<decimal>-<decimal>` in namespace, `.profile-<decimal>-<decimal>` in root). Validate identities, content/ownership where applicable, inclusive budgets and unknowns before deletion. Remove verified data/stages, namespaces and profile marker first, .owner **last** after verifying it against the original still-locked FD. Never recursively walk unknown subtrees.
4. In MVM `spiralcore_payload/installed.rs::create_store` retain original parent Arc, generated leaf and child Arc from mkdirat/openat; compare statat(parent,leaf,NOFOLLOW) with fstat(child). `attach_owned_directory` retains that tuple on the existing permit. `prepare` constructs the lease, attaches it, gives the same lease to the fd constructor and continues existing scope, provisional-session, retain_prepared, seeding and original reader lifecycle. Quarantine preserves all attained originals, including the raw tuple if read-only capture fails and any owner FD or lock attained by Phase 2. On clean joined retirement require the same named child at the original parent before first removal and directly before final rmdir. Fsync original parent and verify absence relative to its FD before releasing the debit. Original reader close/poison/join semantics remain distinct.

Inject failure immediately after open, after lock and before profile/recovery. Actual VM/backend and WAN qualification remain separate milestones.

## Alternatives and review state

The recommended approach places the descriptor-backed implementation inside the shared SpiralCore storage core. That keeps private-file validation, publication, quota and retirement behavior together for both Unix hosts. A provider-implemented filesystem trait could instead leave these operations to each host adapter; it reduces direct core dependencies but expands the backend contract and distributes its security and resource proof across providers. Replacing procfs with another reconstructed pathname does not establish original-directory custody on this Mac.

The component is tracked in [#258](https://github.com/R4-Laboratories/SpiralCore/issues/258), under [#42](https://github.com/R4-Laboratories/SpiralCore/issues/42) and [#44](https://github.com/R4-Laboratories/SpiralCore/issues/44). Independent architecture/security review cleared this proposal for user review after the two-phase custody and namespace binding corrections. The exact original private specification has SHA-256 `1d54272c209f52c5ba84f0f8767c8c794653e05b1ebf8a4197fdf8546013f49a`; this public copy adds alternatives and public tracker links.

**Implementation status.** The approved design has an [implementation plan](../../plans/2026-11-13-unix-owned-store.md). Implementation, native backend qualification and delivery remain pending. The full Ari delivery goal retains its broader platform, sustained-operation, capacity, WAN and security acceptance criteria.
