# UORC v0.3.0 and SpiralCore transfer research

This report records parallel source research on November 10, 2026. UORC offers smaller archives on its published corpora, accompanied by substantial decoding cost. Three mechanisms warrant bounded experiments within SpiralCore's existing protocol. This report authorizes no production codec substitution.

## Mechanisms and exactness

**Code-derived.** Default `steps=0` chooses the smaller complete raw or NCM archive, with an optional reversible x86-address filter. Positive steps enable generated program search. The published benchmark therefore establishes no gain from symbolic synthesis. NCM uses 17 adaptive hashed contexts, a match predictor, three integer neural mixers and two adaptive probability maps driving a 32-bit binary arithmetic coder. Contexts include learned record row length. The default path inspected does not implement CA/Kuramoto replay. [Selection](https://github.com/UOR-Foundation/compression/blob/a4e2222371194b80f7b817922e44c148a9024efa/crates/uorc/src/lib.rs#L172), [NCM](https://github.com/UOR-Foundation/compression/blob/a4e2222371194b80f7b817922e44c148a9024efa/crates/uorc/src/ncm.rs#L1)

UORC schedules 8 MiB frames in four-frame blocks, with two preceding frames of history. Identical earlier frames become references under SHA-256-derived κ basis labels. The frame binds exact object lengths, basis identity, executable representation and a domain-separated SHA-256-chain seal. Reference data belongs to the stream's available basis. Persistent authorized receiver-cache reuse requires an additional integration contract. The integrity seal provides no peer authentication by itself. [Streaming contract](https://github.com/UOR-Foundation/compression/blob/a4e2222371194b80f7b817922e44c148a9024efa/crates/uorc/src/lib.rs#L1), [reference identity](https://github.com/UOR-Foundation/compression/blob/a4e2222371194b80f7b817922e44c148a9024efa/crates/uorc/src/archive.rs#L416)

SpiralCore already binds exact object length and bytes independently of encoding. Its ternary DAG shares fixed leaves, sparse coding exploits matching offsets and prefix/suffix regions, and shared runtime coding reconstructs CA/Kuramoto predictions with checked residuals. Prepared schema and whole-object zstd participate in a byte-oriented selector with lower-bound pruning and acknowledged seeds. A UORC experiment must preserve that identity, authorization and verified publication contract. [Object identity](https://github.com/R4-Laboratories/SpiralCore/blob/a3100c50686347426adb781dfe55bca9aa02baea/crates/spiralcore-transfer/src/lib.rs#L63), [ternary DAG](https://github.com/R4-Laboratories/SpiralCore/blob/a3100c50686347426adb781dfe55bca9aa02baea/crates/spiralcore-transfer/src/dag.rs#L205), [shared runtime](https://github.com/R4-Laboratories/SpiralCore/blob/a3100c50686347426adb781dfe55bca9aa02baea/crates/spiralcore-transfer/src/shared_runtime.rs), [selector](https://github.com/R4-Laboratories/SpiralCore/blob/a3100c50686347426adb781dfe55bca9aa02baea/crates/spiralcore-transfer/src/schema_selection.rs#L305)

The addressing distinction matters for measurements. UORC's standard library is available out of band under a fixed basis identity, and history identities name reconstructed frame content. The release archive totals therefore assume that built-in decoder basis is already installed. SpiralCore's prepared checkpoint, schema and cache objects also require explicit setup accounting, but their recipient authorization and acknowledgment determine which state may actually be referenced. Neither design permits deriving arbitrary new information from an address alone. Any experiment must bind the exact prerequisite bytes and include their first-use delivery, or label the result as conditional on a preinstalled basis.

Within-stream frame references also have different alignment behavior from arbitrary edited-object reuse. Exact 8 MiB repetition is a favorable UORC case. A one-byte insertion can change frame boundaries throughout the remaining stream. Its context history may still help compression, but published aggregate corpus sizes establish no insertion-resilience or persistent-cache advantage. Include both patterns rather than extrapolating exact-repeat savings to sparse edits.

**Inspected finite evidence.** UORC tests cover exact bytes/object boundaries, truncation, canonical framing, flipped integrity bits, wrong basis, reference execution, window history, repeated frames and work refusal. These support the exercised cases. Its compiler/runtime preservation and formal losslessness claims retain their declared trust boundaries, which this review has not independently rechecked. [Conformance tests](https://github.com/UOR-Foundation/compression/blob/a4e2222371194b80f7b817922e44c148a9024efa/crates/uorc/tests/conformance.rs#L108), [window/reference tests](https://github.com/UOR-Foundation/compression/blob/a4e2222371194b80f7b817922e44c148a9024efa/crates/uorc/src/lib.rs#L1504)

UORC saves 31.1% and 20.7% against `zstd -19 --long=27`; all 23 files record exact round trips. ZPAQ produces fewer aggregate Silesia bytes than UORC. These are published file results, with no WAN measurement. [Release measurements](https://github.com/UOR-Foundation/compression/releases/tag/v0.3.0)

The script runs one wall-time trial per tool/file. UORC uses file I/O and available cores, while several comparators use pipes and default thread settings. It records machine memory capacity, not process peak RSS or CPU time. **Inferred illustration**, sequential encoding plus transmission plus decoding reaches parity with zstd around 0.186 Mbps for Canterbury and 0.256 Mbps for Silesia using these observations. This algebra excludes pipelining, authentication and network variation. It is no WAN speed prediction. ## Resource, security and provenance gates

**Code-derived allocation estimate.** At 16 KiB input, NCM reaches approximately 48 MiB probability/count tables, 16 MiB match table and 4.7 MiB other model arrays, totaling about 68.7 MiB before history/output/temporary buffers. This exceeds SpiralCore SmallV1's entire declared 8 MiB paired operation envelope and 512 KiB decoder allowance. Declared allocations and RSS remain distinct. [NCM sizing](https://github.com/UOR-Foundation/compression/blob/a4e2222371194b80f7b817922e44c148a9024efa/crates/uorc/src/ncm.rs#L286), [Small bounds](https://github.com/R4-Laboratories/SpiralCore/blob/a3100c50686347426adb781dfe55bca9aa02baea/crates/spiralcore-transfer/src/resource_profile.rs#L103)

Native fast decoding returns before applying the reference `work` budget. Header-declared body/output sizes need independent admission caps. Frame-reference storage spills after 256 MiB, while reference maps, encoder identities and verification summaries grow with frame count. Streaming decoding needs a seekable header prepass; nonseekable CLI input spools to disk. The spill path uses default file permissions and best-effort removal. An adapter needs bounded private storage, CPU/output/history/reference/thread limits and a fixed admitted decoder profile before receiving untrusted input. [Dispatch](https://github.com/UOR-Foundation/compression/blob/a4e2222371194b80f7b817922e44c148a9024efa/crates/uorc/src/lib.rs#L243), [reference store](https://github.com/UOR-Foundation/compression/blob/a4e2222371194b80f7b817922e44c148a9024efa/crates/uorc/src/store.rs#L26), [spill creation](https://github.com/UOR-Foundation/compression/blob/a4e2222371194b80f7b817922e44c148a9024efa/crates/uorc/src/store.rs#L230)

## Bounded adoption experiments

1. Test an adaptive record/context entropy stage on existing schema values and CA residuals against equally tuned prepared zstd. Charge predictor state and initialization. A smaller model is a new measured variant, with its own decoder/version identity.
2. Borrow the single-pass canonical arithmetic-decoder check, which compares emitted coder bytes during decoding instead of performing a second encode. Preserve exact canonical acceptance with mutation tests. [Implementation](https://github.com/UOR-Foundation/compression/blob/a4e2222371194b80f7b817922e44c148a9024efa/crates/uorc/src/ncm.rs#L1032)
3. Borrow the exact scalar/AVX2/NEON kernel pattern for deterministic arithmetic hot loops. Validate encoded-byte equality and reconstruction across native platforms before selecting acceleration. [Kernel parity](https://github.com/UOR-Foundation/compression/blob/a4e2222371194b80f7b817922e44c148a9024efa/crates/uorc/src/ncm.rs#L1131)

Use a fixed corpus covering structured text/binary records, CA predictions, already-compressed data and ciphertext. Include exact repeats, localized/scattered edits, insertion/deletion, cold receivers and persistent warm sessions. Start at Small's 16 KiB and separately admit 1–16 MiB bulk objects under explicit budgets. Compare raw, equally tuned whole/prepared zstd, existing SpiralCore selection and optional UORC, retaining every loss.

Run randomized paired trials with matched thread/core allowances. Record exact reconstruction/readback, complete encoded and setup bytes, reference/basis costs, acknowledgments and authenticated traffic both ways, sender/receiver CPU, peak RSS, scratch/durable bytes and verified total time. Preserve Small's existing envelope. After local qualification, execute the same authenticated paired-gateway path on actual WAN, with seed costs amortized explicitly. Publish the byte/CPU/time Pareto frontier; adopt a candidate only within the workload and resource envelope it actually improves.
